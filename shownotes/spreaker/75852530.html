Many digital twin projects start with a 3D factory scene or every PLC tag and end up with a graph nobody can use. This episode is for manufacturing IT and OT architects building on Azure and explains what deserves a twin, how to model identity, state, events and relationships, and where Azure Digital Twins fits next to ERP, MES and APS. You will leave with five questions to test any twin before you build it.

In this episode

  • 00:00 – Start with the decision, not the asset
  • 05:20 – What a twin really is: an instance with context
  • 10:40 – Digital twin, device twin, 3D model and simulation
  • 16:35 – Model identity before telemetry
  • 21:40 – State, telemetry and events
  • 37:20 – Relationships, structures and the order twin
  • 63:40 – DTDL, model boundaries and five questions
  • 91:40 – Azure Digital Twins as the context layer and source ownership

Key takeaways

  • Start a digital twin with a repeating decision and the person who makes it, then model only the entities, state and relationships that change that decision.
  • Give every entity one stable twin ID, keep raw telemetry in time series storage and put only trusted current state with source, time and quality on the twin.
  • Azure Digital Twins is the context layer that connects ERP, MES, APS and PLC facts through DTDL models and relationships, while each source system keeps ownership of its own facts.
