Manual kubectl fixes and configuration drift make Kubernetes clusters behave in ways nobody can explain. This episode explains GitOps for Azure and Kubernetes engineers: declarative state in Git, pull-based deployments, the reconciliation loop, Flux versus Argo CD and the built-in GitOps support in AKS. You learn how to get trivial rollbacks, self-healing clusters and a built-in audit trail.

Key takeaways

  • GitOps makes Git the single source of truth for infrastructure, so the cluster always matches what is declared and versioned in the repository.
  • In the pull-based model an operator such as Flux or Argo CD reconciles the cluster with Git continuously, which removes drift and keeps cluster credentials out of CI pipelines.
  • On Azure, Flux v2 is built into AKS and Azure Arc, so a team can start with one small cluster pointed at a Git repo and gain instant rollbacks and a full audit trail.

Worth quoting

“Git becomes your single source of truth, not just for your code, but for everything your infrastructure needs to run. Every configuration, every deployment, manifest, every environment variable, it all lives in Git.” – Mirko Peters (02:11)
