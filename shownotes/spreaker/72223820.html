Copilot can talk, but complex business logic breaks standard connectors and low-code flows. This episode is for developers and architects who want to build Copilot plugins that actually execute work at enterprise scale. Learn how to combine Azure Functions, OpenAPI specs, API Management and durable functions into a fast, secure and maintainable architecture.

In this episode

  • 00:00 – Why standard connectors fail at scale
  • 03:52 – The architecture choice: Azure Functions and Flex consumption
  • 12:14 – OpenAPI specs as the semantic contract for Copilot
  • 18:38 – C# Azure Functions, identity and network security
  • 25:45 – DLP bypass risk and API Management as the security front door
  • 32:27 – Durable functions, latency optimization and monitoring
  • 43:32 – Testing, versioning, cost optimization and CI/CD
  • 58:18 – Invoice validation plugin, pitfalls and scaling to the enterprise

Key takeaways

  • Standard connectors and low-code expressions hit limits on heavy business logic, so the fusion developer model extends Power Platform with Azure Functions connected through OpenAPI specs and custom connectors.
  • Flex consumption with always-ready instances removes most cold starts, and OpenAPI specs must be written for the language model with clear operation IDs, intent-based descriptions, examples and error schemas.
  • Production plugins need managed identities, Entra ID authentication, private endpoints and API Management in front of the function to prevent DLP bypasses, plus monitoring, versioning and CI/CD to scale safely.
