Some workloads cannot leave the factory, hospital or store, yet running them on isolated local servers splits teams and tools. This Simply Explained episode helps IT pros and architects understand what Azure Local is, how it differs from Azure Arc, and when bringing Azure management to on-premises workloads really makes sense.

Key takeaways

  • Azure Local runs virtual machines, containers and selected Azure services on validated hardware at your own site, while Azure provides management, monitoring, policy and security.
  • Azure Arc is the management layer that connects any outside infrastructure to Azure, whereas Azure Local is the hyperconverged platform where local workloads actually run.
  • Choose Azure Local when latency, data location rules, required offline operation or direct control demand it, and start every decision with the workload rather than the hardware.

Worth quoting

“Keeping data local isn't always about distrust of the cloud. Sometimes it's about law, sometimes about speed, and sometimes about keeping the business running when the network fails.” – Mirko Peters (02:41)

“Azure local doesn't copy all of public Azure into a rack of servers. You don't suddenly get every Azure service running locally just because you installed Azure local.” – Mirko Peters (04:19)
