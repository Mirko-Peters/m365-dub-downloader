Microsoft 365 development is moving from SharePoint toward Teams, Copilot extensibility and agentic AI. In this interview, five-time MVP and PnP maintainer Gautam Sheth explains what PnP PowerShell and PnP .NET solve, how open source is maintained and how GitHub Copilot changes daily development. A practical episode for Microsoft 365 developers and admins who automate with PnP and AI.

Key takeaways

  • PnP PowerShell and PnP .NET are community-maintained, open-source tools that fill gaps in Microsoft's own SharePoint and Graph tooling, including fluent APIs and robust throttling handling, but they are not supported by Microsoft.
  • Development focus is shifting from SharePoint toward Teams apps and Copilot extensibility, with PnP exploring an MCP server and agent skills for AI-driven workflows.
  • AI and GitHub Copilot accelerate development, but developers still need language fundamentals, least-privilege permissions and governance to stay responsible for the code they ship.

Worth quoting

“whenever a developer has to develop on top of PNP.NET or PNP PowerShell on all of that, they should always consider the least permissions that they might need to execute certain operations” – Gautam Sheth (26:15)

“one of the misconceptions is that PNP PowerShell is Microsoft developed. It is not, it is completely open source. It is maintained by a team of maintainers who spend their time outside of work” – Gautam Sheth (26:49)
