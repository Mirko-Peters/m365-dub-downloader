Many teams assume Microsoft takes care of networking in the cloud, then find gaps in security and routing later. Azure MVP Rex de Koning explains to cloud architects and admins how Azure networking really works, from hub-and-spoke and Virtual Network Manager to securing Azure Functions. You come away with practical guidance on building network foundations with infrastructure as code.

In this episode

  • 00:00 – Why networking is the foundation
  • 02:11 – Rex's path into Azure
  • 06:54 – Azure networking misconceptions and topologies
  • 13:50 – Azure Virtual Network Manager
  • 24:22 – Landing zones and infrastructure as code
  • 42:01 – Securing Azure Functions
  • 51:19 – Final advice

Key takeaways

  • In Azure, routing happens at the resource level, so network security groups remain essential even behind a central firewall.
  • Azure Virtual Network Manager centralizes IP address management, connectivity, security admin rules and routing across many virtual networks.
  • Deploy networks and Azure Functions through infrastructure as code with private endpoints and VNet integration, and feed any emergency portal fix back into code.

Worth quoting

“And with Azure Virtual Network Manager, you have basically an admin rule that you can push towards all network security groups that are connected to the Azure Virtual Network Manager.” – Rex de Koning (17:34)

“So if you set it up in infrastructure as code that it has multiple advantages, it will always set things up always in the same way that you want it.” – Rex de Koning (30:03)
