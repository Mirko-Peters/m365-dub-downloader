Growing service teams quickly find that one shared queue sends urgent cases to the wrong people or leaves them waiting. This episode explains Dynamics 365 unified routing for customer service leads and admins. You learn how workstreams, queues, skills and capacity work together so every request reaches the right agent the first time.

In this episode

  • 00:00 – Requests stuck in a shared queue
  • 00:33 – Why basic queues stop working
  • 03:00 – Classification and assignment
  • 06:50 – Workstreams, queues, skills and capacity
  • 11:23 – One request from message to agent
  • 14:49 – Planning a routing model
  • 17:37 – Conclusion

Key takeaways

  • Unified routing first classifies incoming work with skills, language and priority, then assigns it to an available agent who has the right skills and free capacity.
  • Workstreams define the path for each kind of work, queues set team ownership, skills describe fit, and capacity profiles plus presence show who can take work now.
  • Build queues, people, skills and capacity before routing rules, keep rules minimal, and give the fallback queue an owner who watches it.

Worth quoting

“A queue only answers part of the question, it can tell you where a request should wait, but it doesn't always decide which available person has the right knowledge, who already handles several chats, or whether a more urgent request should come first.” – Mirko Peters (01:34)

“Your service leaders still decide which customers need faster help, what skills matter, how many chats an agent can manage, and where work should go when nobody matches. Unified routing takes those decisions and applies them the same way each time.” – Mirko Peters (02:36)
