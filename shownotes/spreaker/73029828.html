Most Azure security incidents start with an overly permissive rule, not a sophisticated exploit. This episode is for Azure beginners and administrators who deploy virtual machines and subnets. You learn how NSG rules, priorities, service tags and application security groups work and which mistakes leave your environment wide open.

In this episode

  • 00:00 – Why an Azure VM without an NSG is an unlocked door
  • 01:55 – What a network security group is
  • 04:09 – How NSG rules work: priority and defaults
  • 06:39 – Common misconfigurations
  • 08:47 – Best practices for NSG rules
  • 10:25 – NSG vs Azure Firewall
  • 12:14 – Walkthrough: creating and applying an NSG

Key takeaways

  • A network security group filters traffic at layers three and four by source, destination, port and protocol, and it is stateful, free and the first line of defense in Azure.
  • Rules are evaluated by priority with the first match winning, so leave gaps between priorities, attach one NSG per subnet and check effective security rules when troubleshooting.
  • Avoid opening sensitive ports to the internet, use application security groups and service tags instead of hard-coded IPs, and add Azure Firewall when you need centralized deep inspection.

Worth quoting

“It works at layers three and four of the network model, which means it looks at IP addresses, ports and protocols without digging into the actual content of the traffic.” – Mirko Peters (02:19)

“NSGs are stateful. What does that mean? If you allow inbound traffic on port 80, the reply traffic goes back out automatically.” – Mirko Peters (02:57)
