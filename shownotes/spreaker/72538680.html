Security defaults and one-time setups leave identities exposed while attackers use phishing, password reset abuse and guest accounts to get in. This episode is for Microsoft 365 and Azure admins, architects and MSPs who need to secure identities at scale. Microsoft MVP Jonathan Hope shares his foundation Conditional Access policies and why Bicep and policy as code make security repeatable.

In this episode

  • 00:00 – Welcome and Jonathan Hope's path from VMware to Azure
  • 02:47 – Identity as the new perimeter
  • 09:44 – How attackers target identities
  • 15:18 – Active Directory, hybrid identity and cloud-first groups
  • 19:28 – Conditional Access and the six foundation policies
  • 26:25 – AI, Zero Trust and Azure versus identity security
  • 34:46 – Infrastructure as code with Bicep
  • 45:11 – Policy as code, the security roadmap and quick-fire round

Key takeaways

  • Identity is the new perimeter, and Conditional Access acts as a real-time firewall that evaluates every access request using signals from Intune, Defender and Purview.
  • A small set of foundation policies such as MFA for all users, stronger methods for admins, blocking device code flow and legacy authentication, and country controls stops most low-hanging attacks.
  • Infrastructure as code with Bicep and policy as code turn security configurations into repeatable, documented standards that keep up with constant portal changes.

Worth quoting

“It's the modern day cloud identity and workload firewall in the modern cloud. Identity is the server. It's a control plane that every access request goes through.” – Jonathan Hope (20:22)
