Is your app still asking Microsoft Graph every few minutes whether anything has changed? This episode explains to Microsoft 365 developers how Graph webhooks replace polling with change notifications, how subscriptions and validation work, and why combining them with Delta query gives you integrations that are both fast and reliable.

In this episode

  • 00:00 – Intro: the mailbox analogy
  • 00:43 – The polling problem and Graph throttling
  • 02:23 – What are webhooks?
  • 04:10 – How Microsoft Graph webhooks work
  • 06:10 – Creating a subscription
  • 08:40 – The validation handshake
  • 10:32 – Handling notifications, security and lifecycle
  • 16:17 – Real-world example and next steps

Key takeaways

  • Polling Microsoft Graph wastes thousands of requests, still misses real-time changes and can push your app into throttling.
  • A Graph webhook needs a subscription with notification URL, resource, change type and expiration, plus a validation handshake that echoes the token as plain text.
  • Acknowledge notifications within seconds, process them asynchronously, renew subscriptions before they expire and use Delta query as a safety net for missed changes.

Worth quoting

“A web hook is an HTTP request sent automatically when something happens. You don't ask for it. The server just pushes it to you.” – Mirko Peters (02:30)

“Acknowledge immediately and process asynchronously. Your endpoint should validate the client state, accept the notification, and return it 200 or 202 responses as fast as possible.” – Mirko Peters (12:22)
