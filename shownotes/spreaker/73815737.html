In many Dynamics 365 projects, every automation request ends up as custom code in a developer backlog, and the business pays for it every time a rule changes. This episode shows Dynamics and Power Platform teams where plug-ins still belong, how to make automation visible and owned, and how to migrate safely to Power Platform as the real automation layer.

In this episode

  • 00:00 – Automation as a development backlog
  • 04:25 – The hidden cost of custom code
  • 08:40 – Where custom code still belongs
  • 12:14 – Reasoning between event and action
  • 16:46 – Sales approval without a plug-in
  • 24:06 – Ownership, solutions and environments
  • 35:20 – Governance, DLP and Dataverse security
  • 51:09 – Inventory, migration and a 90-day reset

Key takeaways

  • Keep plug-ins narrow for transactional validation and performance-critical work, and move orchestration across people, systems and time into Power Platform.
  • Business-critical flows need organizational identities, solutions with environment variables and managed deployments instead of personal ownership and production edits.
  • Governance through environments, DLP policies and Dataverse security is an operating model that lets automation scale, starting with an inventory rather than a rewrite.

Worth quoting

“This isn't an argument against developers, it's an argument against using developers as the routing layer for every business process change.” – Mirko Peters (03:36)
