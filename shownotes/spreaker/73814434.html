If your project folders are named final, final-final and use-this-one, Git is the fix. This episode explains Git in plain English for beginners, makers and Microsoft 365 builders: commits, the staging area, branches, merges, conflicts and how GitHub and pull requests fit into a team workflow.

In this episode

  • 00:00 – Git is your project history
  • 03:26 – The three local areas: working directory, staging area, repository
  • 07:17 – Branches, merges and conflicts
  • 10:46 – GitHub, the shared online repository
  • 13:55 – A Git-based team workflow
  • 15:55 – CI/CD, AI and the daily route

Key takeaways

  • Git is a local-first version control system that records deliberate, named checkpoints called commits, so you can see what changed and return to an earlier version.
  • Changes move from the working directory through the staging area into the local repository, while branches let you work safely without disturbing the trusted main version.
  • GitHub adds a shared remote repository and pull requests for review and automated checks, turning separate computers into one team workflow: work, stage, commit, push, review, merge.

Worth quoting

“So think of Git as your project's memory, not a magic undo button, and not a coding language. It's a system for creating deliberate, named checkpoints that you can inspect later” – Mirko Peters (03:10)

“Git is the tool that tracks your project history. GitHub is an online place where people can share that history.” – Mirko Peters (02:29)
