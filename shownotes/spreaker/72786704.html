Portal clicks feel fast, but they quietly create configuration drift that breaks governance at scale. This episode is for Azure architects and platform teams deciding between ARM, Bicep and Terraform, and it explains how infrastructure as code, policy as code and guardrails keep both humans and AI agents under control.

In this episode

  • 00:00 – The death of ClickOps and configuration drift
  • 07:22 – From imperative to declarative infrastructure
  • 10:26 – ARM templates: the necessary mistake and cognitive load
  • 17:48 – Bicep: designed for humans, compiled for machines
  • 23:56 – Drift as a governance epidemic and IaC as the control plane
  • 30:41 – AI agents, guardrails and Bicep vs. Terraform
  • 41:44 – Governance as an operating model and continuous compliance
  • 55:14 – Infrastructure as intent, lessons and next steps for leaders

Key takeaways

  • Configuration drift from manual portal changes is a governance failure, and only declarative infrastructure as code makes the actual state visible, reviewable and correctable.
  • Bicep compiles to ARM JSON but removes its syntax noise, which is why new Azure projects default to it while legacy ARM templates persist because of switching costs.
  • AI agents can generate infrastructure code quickly, but it must flow through policy as code, human review and CI/CD so that automation never outpaces control.

Worth quoting

“If you treat it like a technical problem, you'll miss what's actually happening. You'll spend money on tools and miss the structural failure underneath because drift is a governance failure.” – Mirko Peters (04:00)

“AI agents must operate within policy guardrails, not autonomously, not with broad permissions, not trusted to make security decisions without oversight. They generate proposals, policies validate those proposals, humans review the validated output.” – Mirko Peters (34:06)
