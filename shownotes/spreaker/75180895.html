Sending all factory data to the cloud looks cheap until egress, cross-zone traffic, replication and dashboards show up on the invoice. This episode shows manufacturing and cloud architects how to model the real cost of data movement and build an edge-first pattern that scales. You will learn which data should stay local and which earns a trip to the cloud.

  • 01:02 – Egress, boundaries and data paths

  • 28:08 – Data half-life and the value hierarchy
  • 44:09 – Data gravity
  • 49:06 – Zones, NAT, replication and return paths
  • 82:17 – Edge processing, filtering and aggregation
  • 110:35 – The three-layer factory data pattern

Key takeaways

  • Factory cloud cost is driven by data movement across boundaries, zones, gateways and return paths, not just by storage.
  • Estimate volume from sample rate, payload size and retention rather than device count, and move data only when a named consumer needs it for a named decision.
  • Use an edge, site and cloud layer pattern: filter, aggregate and infer near the machine, and send governed operational facts to the cloud.
