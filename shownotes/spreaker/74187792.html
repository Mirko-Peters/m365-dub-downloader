Enterprise integration is usually invisible until it breaks, and deterministic workflows struggle with the unexpected. This episode is for architects and integration developers who want to understand Azure Logic Apps, connectors, identity and observability, and how agent loops can make integrations adaptive and self-healing.

In this episode

  • 00:00 – Intro: integration as a commodity
  • 02:05 – Sonny's path into integration and why enterprise integration gets complex
  • 07:29 – What Azure Integration Services include
  • 11:29 – Logic Apps, CI/CD, infrastructure as code, consumption vs. standard
  • 20:38 – The connector ecosystem and its security trade-offs
  • 27:11 – Authentication, managed identities and least privilege
  • 30:59 – Observability, tracked properties and business-driven logging
  • 49:37 – Organism as a Service: agent loops and self-healing integrations

Key takeaways

  • Azure Integration Services combine Logic Apps, API Management, Azure Functions, Service Bus and Event Grid, and the right mix depends on whether a team prefers low code or pro code.
  • Secure integrations rely on built-in connectors where possible, managed identities, Key Vault and least-privilege permissions so that one breached connection cannot take down every integration.
  • With agent loops in Logic Apps, integrations can interpret errors and intent and react to unexpected situations, turning integration as a service into what Sonny Gillissen calls Organism as a Service.
