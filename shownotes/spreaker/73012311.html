Connection strings in config files, leaked secrets on GitHub and certificates expiring at 3 a.m. are everyday pain for Azure teams. This episode explains managed identities in plain English for developers and cloud admins: the two types, how tokens are issued and where the limits are. You will learn how to replace secrets with permissions in your own workloads.

Key takeaways

  • Managed identities give Azure resources their own Entra ID identity so code obtains tokens from IMDS instead of storing connection strings or client secrets.
  • Use system-assigned identities for a single resource with zero overhead and user-assigned identities when several resources share permissions or the identity must outlive them.
  • Managed identities only work for workloads running in Azure; outside Azure use service principals with Key Vault or workload identity federation.

Worth quoting
