Cloud networks have no single front door, so a physical firewall at the edge no longer protects your workloads. This episode is for Azure admins and anyone new to Azure networking, and explains what Azure Firewall does, how its SKUs, rules and hub-and-spoke placement work, and which setup to start with today.

In this episode

  • 00:00 – A security desk for a building without walls
  • 00:47 – What a firewall is
  • 01:43 – Why cloud firewalls are different
  • 03:01 – Introducing Azure Firewall
  • 04:20 – The three SKUs: Basic, Standard and Premium
  • 06:35 – Architecture and traffic flow
  • 08:25 – Rules deep dive: NAT, network and application rules
  • 10:22 – Advanced protection, cost tips and next steps

Key takeaways

  • Azure Firewall is a fully managed, cloud-native firewall service with built-in high availability and autoscaling that inspects inbound, outbound and east-west traffic.
  • Basic, Standard and Premium SKUs add capabilities step by step, from IP and port filtering to threat intelligence in deny mode, web categories, TLS inspection, IDPS and URL filtering.
  • Traffic is only inspected if it passes through the firewall, so a hub-and-spoke design, correctly ordered NAT, network and application rules, and cost controls like the Log Analytics basic table plan matter as much as the SKU.

Worth quoting

“You can't install a physical firewall box in a data center you don't own. And even if you could, it wouldn't help because there's no single door to guard anymore.” – Mirko Peters (01:37)

“Both directions need inspection. If a hacker gets into one workload, you don't want them roaming freely to others. That's how breaches spread.” – Mirko Peters (02:20)
