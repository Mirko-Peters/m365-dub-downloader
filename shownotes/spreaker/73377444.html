Many organizations have moved workloads to Azure but still run it like a traditional data center. In this interview, Microsoft MVP Jev Suchoi explains to cloud architects, platform teams and IT leaders how Azure landing zones, the Cloud Adoption Framework, Azure Policy and infrastructure as code combine into a secure self-service platform developers want to use.

Key takeaways

  • Azure should not be treated as a data center: cloud success is an adoption exercise across people, processes and technology, not only a technical migration.
  • An Azure landing zone separates the platform landing zone for shared security, management, networking and identity from application landing zones built from subscriptions with pre-provisioned utilities and policies.
  • Platform engineering builds standardized, self-service building blocks for developers, using Azure Policy remediation, infrastructure as code with Bicep or Terraform, Azure Verified Modules and Azure DevOps or GitHub as guardrails that help rather than block.

Worth quoting

“It's not a data center and you should not treat it as well. I think that's the most fundamental, the biggest mistake or anti-pattern that exists when we're talking about moving workloads, applications, anything to Azure.” – Jev Suchoi (13:40)
