Impressive AI demos are easy, but turning agents into reliable business automation is hard. In this interview, Microsoft MVP David Lorenzo Lopez explains to makers, developers and architects how multi-agent systems work in Copilot Studio, Microsoft Foundry and the Microsoft Agent Framework. You learn when to use which platform, where humans must stay in the loop and how to keep cost and governance under control.

  • 05:21 – What multi-agent systems are: from monolith to microservices
  • 10:41 – Orchestration, agent collaboration and human approval
  • 18:10 – Building in Copilot Studio and Foundry with agent flows and workflows
  • 24:35 – Starting customer projects and EU AI Act compliance
  • 31:00 – Copilot Studio vs. Foundry and the Microsoft Agent Framework
  • 39:33 – FinOps, Agent 365 governance and quick-fire round

Key takeaways

  • Multi-agent systems split one overloaded agent into specialized agents coordinated by an orchestrator, similar to the move from monoliths to microservices, which makes them easier to test and reuse.
  • Choose Copilot Studio, Foundry low-code or the Microsoft Agent Framework based on licensing, data location, performance and customization needs, and keep critical operations behind human approval.
  • Not every automation needs AI; deterministic agent flows with AI only at specific steps, careful cost estimation and central governance with Agent 365 make agent projects deliver real value.
