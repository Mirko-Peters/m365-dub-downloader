Many Azure deployments run into trouble because the virtual network underneath was treated as a checkbox. This episode is for cloud beginners, administrators and architects who deploy workloads in Azure. You learn how address spaces, subnets, IPs, NSGs, routing and peering fit together so your network is secure and ready to grow.

In this episode

  • 00:00 – What an Azure Virtual Network is
  • 02:09 – IP addressing and CIDR
  • 04:31 – Subnets: dividing your network
  • 07:02 – Public and private IPs
  • 08:55 – Network security groups
  • 10:50 – Route tables and user-defined routes
  • 12:41 – VNet peering and hub-and-spoke
  • 14:48 – How it all connects

Key takeaways

  • An Azure Virtual Network is a regional, private network boundary, and its address space should be planned large enough and free of overlaps before anything is deployed.
  • Subnets separate application tiers, private IPs should be the default, and network security groups plus route tables control what traffic is allowed and where it goes.
  • VNet peering connects networks privately over the Microsoft backbone but is not transitive, so growing environments typically use a hub-and-spoke design.

Worth quoting

“Your VNet's address space cannot overlap with any other network you plan to connect to. This is a common mistake.” – Mirko Peters (03:10)

“Public IPs are optional. You assign them explicitly because Azure never gives your resources a public IP unless you ask for it. That's by design, the default should be private and public should be a deliberate choice.” – Mirko Peters (07:43)
