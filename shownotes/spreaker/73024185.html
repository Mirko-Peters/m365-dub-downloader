Running containers often feels like a choice between a single container and a full Kubernetes cluster that needs its own team. This episode is for developers and small teams who want modern container features without becoming Kubernetes admins: it explains Azure Container Apps, how KEDA, Dapr and Envoy power it, its limits, and what it costs.

Key takeaways

  • Azure Container Apps sits between Azure Container Instances and AKS, offering Kubernetes-level features like autoscaling, ingress and revisions while Microsoft manages the cluster.
  • KEDA, Dapr and Envoy provide event-driven scaling to zero, microservice building blocks and managed ingress with traffic splitting out of the box.
  • Start new container projects on Container Apps and move to AKS only if you need Helm, custom resources, Windows containers or full cluster control.

Worth quoting

“Most people don't need either extreme. They want something in the middle, and that middle ground is exactly where Azure Container apps lives.” – Mirko Peters (01:45)

“Traditional auto-scaling watches CPU or memory. If your CPU hits 80%, spin up another instance. That works, but it's reactive. By the time your CPU is high, your users have already felt the lag.” – Mirko Peters (05:39)
