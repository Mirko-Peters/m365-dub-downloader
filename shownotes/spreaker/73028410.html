Users in Tokyo should not wait on a single server in Virginia, and one regional outage should not take your whole app offline. This episode explains Azure Traffic Manager for developers and cloud architects building multi-region apps: how DNS-based routing works, when to use each of its six routing methods, and how it fits alongside Load Balancer, Application Gateway and Front Door.

In this episode

  • 00:00 – Why global traffic routing matters
  • 02:32 – What Traffic Manager actually is
  • 04:16 – Priority routing for disaster recovery
  • 05:58 – Performance routing
  • 07:42 – Weighted and geographic routing
  • 10:57 – Multi-value and subnet routing
  • 12:26 – Health monitoring and failover
  • 14:22 – Decision guide: Traffic Manager vs. other options

Key takeaways

  • Azure Traffic Manager is a DNS-based global traffic director that never sits in the data path, so it adds no latency to user connections.
  • Its six routing methods cover different goals: priority for disaster recovery, performance for speed, weighted for canary releases, geographic for compliance, plus multi-value and subnet for niche cases.
  • Reliable failover depends on well-tuned health probes against a lightweight health endpoint and on regularly testing that backup regions can carry the full load.
