Many Azure admins assume their storage accounts and databases are private just because they run in Azure, but they are reachable from the internet by default. This episode explains Azure Private Link in plain English for cloud beginners and IT pros, covering private endpoints, DNS, alternatives like VPN and ExpressRoute, costs and the gotchas to avoid.

  • 00:50 – The old way: public endpoints everywhere

  • 08:08 – Private Link vs. VPN, ExpressRoute and service endpoints
  • 10:11 – Private Link service for your own applications
  • 11:47 – Security, compliance and cost
  • 13:36 – Implementation gotchas and takeaway

Key takeaways

  • Azure PaaS services such as Storage, SQL and Key Vault ship with public endpoints, and a subscription is a billing boundary, not a network boundary.
  • Azure Private Link places a private endpoint with a private IP inside your virtual network, and private DNS zones make the existing service URL resolve to it so applications need no changes.
  • Creating a private endpoint does not disable public access, on-premises clients need DNS forwarding, and the extra per-endpoint cost is best justified for sensitive, regulated production workloads.

Worth quoting

“Your subscription is a billing and management boundary, not a network boundary. By default, your Azure services are reachable from the internet.” – Mirko Peters (02:08)

“Enabling a private endpoint does not turn off the public endpoint automatically. They can both exist at the same time. If you create a private endpoint, but never touch the public endpoint settings, your storage account is still reachable from the internet.” – Mirko Peters (03:25)
