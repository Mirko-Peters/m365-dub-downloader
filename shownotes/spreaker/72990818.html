Most Azure users never notice the engine behind every deployment. This episode explains Azure Resource Manager in plain English for Azure beginners and admins, covering RBAC, resource groups, policies and ARM templates so deployments become consistent, governed and repeatable.

In this episode

  • 00:00 – What Azure Resource Manager actually is
  • 02:15 – Authentication and authorization with RBAC
  • 03:48 – Resource groups
  • 05:58 – Tags, locks and policies
  • 08:28 – Infrastructure as code with ARM templates
  • 10:32 – Real-world scenario: deploying a web app
  • 12:25 – How it all fits together
  • 14:22 – Actionable takeaways

Key takeaways

  • Azure Resource Manager is the control plane every portal click, CLI command and template passes through, which is why results are consistent.
  • Resource groups, RBAC, tags, locks and Azure Policy form one governance system that ARM enforces on every request.
  • ARM templates and Bicep make deployments declarative and repeatable; export a template from an existing resource group to get started.

Worth quoting

“Every request to create, update, or delete a resource goes through ARM first. It doesn't matter how you make that request, whether it's through the Azure portal, the command line, power shell, or the SDKs, they all hit the same front door.” – Mirko Peters (01:02)

“Here's the rule you need to remember. Every single resource in Azure must belong to exactly one resource group, no exceptions.” – Mirko Peters (04:15)
