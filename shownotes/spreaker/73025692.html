Most organizations store the same customer and sales data four or five times, and nobody trusts which report is right. This episode explains Microsoft Fabric OneLake for data engineers, analysts and Power BI users: the OneCopy principle, shortcuts, mirroring, the three data stores and a single security model.

In this episode

  • 02:13 – What OneLake is
  • 03:44 – The OneCopy principle
  • 05:27 – Shortcuts: leave data where it lives
  • 06:57 – Mirroring database data
  • 08:50 – Lakehouse, Warehouse and Eventhouse
  • 10:59 – Security and governance
  • 12:33 – Practical takeaways

Key takeaways

  • OneLake is a single logical data lake per tenant, built on Azure Data Lake Storage Gen2 and delivered as a SaaS service, where every Fabric workload stores its data in open Delta Parquet format.
  • The OneCopy principle lets Spark, SQL and Power BI read the same physical data, while shortcuts reference external data in place and mirroring replicates databases in near real time without pipelines.
  • Lakehouse, Warehouse and Eventhouse are different views over the same storage, governed by one security model with workspace roles, OneLake security roles, the OneLake catalog and Purview integration.

Worth quoting

“One copy means one source of truth when the data updates every report sees the update immediately. No more asking, is this report using last week's data or this week's?” – Mirko Peters (04:51)

“A shortcut is a virtual pointer. Think of it like a symbolic link for your data lake. And it lets you access data that physically lives outside one lake without moving or copying it.” – Mirko Peters (05:31)
