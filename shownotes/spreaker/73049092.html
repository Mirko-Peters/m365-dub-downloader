Copilot cannot answer questions about data that lives in your CRM, ticketing system or wiki unless you connect it. This episode helps Microsoft 365 admins and Copilot owners understand Graph and Copilot connectors, choose between synced and federated models, and keep permissions and compliance intact.

  • 05:41 – Synced connectors deep dive
  • 07:38 – Federated connectors deep dive
  • 11:21 – Security and compliance
  • 13:09 – Getting started and wrap-up

Key takeaways

  • Out of the box, Microsoft 365 Copilot only sees Microsoft 365 content; Graph connectors, now called Copilot connectors, bring external systems such as Salesforce, ServiceNow or Confluence into reach.
  • Synced connectors copy and semantically index data into Microsoft Graph, while federated connectors query the source live through the Model Context Protocol and store nothing in Microsoft 365.
  • Every connected item needs a correct access control list, and many organizations combine synced connectors for static knowledge with federated connectors for live operational data.

Worth quoting

“A Graph connector is a piece of software that brings external data into the Microsoft Graph. Now, the Microsoft Graph is the same index that powers Microsoft Search, SharePoint Search, and now Copilot.” – Mirko Peters (02:40)

“With a federated connector, no data gets stored in Microsoft 365 at all. When a user asks co-pilot a question, co-pilot sends a request to the external system using the model context protocol or MCP.” – Mirko Peters (07:44)
