Many organizations want AI agents but struggle to move from demo to a trustworthy enterprise solution. This episode is for Microsoft 365 architects, makers and governance leads, and covers with MVP Reshmee Auckloo how to roll out Copilot responsibly and design multi-agent solutions with Copilot Studio, Foundry, MCP and SharePoint.

In this episode

  • 00:00 – Introduction and Reshmee's journey into Microsoft technologies
  • 03:33 – Responsible Copilot adoption, permissions and Purview
  • 08:52 – Customer concerns about AI and keeping up with change
  • 15:04 – Microsoft Build announcements and Copilot readiness
  • 23:03 – Copilot extensibility: from SharePoint agents to Foundry
  • 31:55 – Multi-agent systems, autonomy and MCP
  • 44:19 – Identity, governance, metadata and information architecture
  • 51:25 – Quick-fire round and community contributions

Key takeaways

  • Rolling out Copilot safely starts with permission hygiene and Purview guardrails, because Copilot surfaces any data a user already has access to.
  • Copilot extensibility spans SharePoint agents, Agent Builder, Copilot Studio, the Agents Toolkit and Microsoft Foundry, and the right choice depends on the use case.
  • Multi-agent solutions use an orchestrator with smaller specialized agents that are easier to test and maintain, while MCP tools, Entra-based agent identity and good metadata keep them controllable.

Worth quoting

“it's very important to think security governance before trying to go for the speed to deployment onto production.” – Reshmee Auckloo (08:26)
