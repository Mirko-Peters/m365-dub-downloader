Billions of IoT devices ship without secure boot or a way to patch them. This episode explains Azure Sphere in plain English for IoT developers, architects and security teams, showing how Microsoft secures devices from the chip to the cloud and when the platform is worth the trade-offs.

In this episode

  • 00:00 – Why IoT devices were never built to be secure
  • 01:32 – What Azure Sphere actually is
  • 03:32 – Layer 1: the silicon and Pluton
  • 05:53 – Layer 2: the locked-down Linux OS
  • 08:14 – Layer 3: the Azure Sphere Security Service
  • 11:46 – How the three layers work together
  • 14:42 – Vulnerabilities and the honest picture
  • 16:52 – Who Azure Sphere is for

Key takeaways

  • Azure Sphere combines a certified microcontroller, a locked-down Linux-based OS and a cloud security service, so IoT security starts at the silicon instead of being bolted on later.
  • The Pluton security subsystem provides a hardware root of trust and secure boot, while Microsoft pushes mandatory OS updates and certificate-based authentication to every device for at least ten years.
  • Azure Sphere is worth it for long-lived industrial, commercial, infrastructure and healthcare devices where a breach would cost more than the device, not for cheap home gadgets.

Worth quoting

“Azure Sphere takes a different approach, security is built in from the start, not added later, the chip itself has security features baked into the silicon, the operating system is designed specifically to run securely, the cloud service manages the whole fleet” – Mirko Peters (02:32)

“Because every line of code is a potential vulnerability. The more code you have, the more bugs you can have. By keeping the operating system small, Microsoft reduces what security researchers call the trusted computing base.” – Mirko Peters (06:31)
