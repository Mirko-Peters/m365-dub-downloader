Juggling separate tools for tasks, code, testing and deployment that never talk to each other? This episode explains Azure DevOps in plain English for beginners, makers and IT pros, and shows how its five connected services take a feature from idea to production.

In this episode

  • 00:00 – Intro: too many disconnected tools
  • 01:08 – What Azure DevOps is
  • 02:37 – Azure Boards: planning and tracking
  • 05:04 – Azure Repos: version control with Git
  • 07:00 – Azure Pipelines: CI/CD automation
  • 09:27 – Azure Test Plans: structured testing
  • 11:49 – Azure Artifacts: shared packages
  • 13:35 – How it all fits together and first steps

Key takeaways

  • Azure DevOps is one connected platform of five services: Boards for planning, Repos for code, Pipelines for automation, Test Plans for quality and Artifacts for packages.
  • Linking work items, commits, pipeline runs, test cases and bugs gives full traceability from a user story to the deployed feature.
  • Start small on the free tier: create a project in Boards, track a few tasks, then add Repos and Pipelines one step at a time.

Worth quoting

“It's one connected platform that handles the entire software development lifecycle, planning, coding, testing, deploying, all in one place.” – Mirko Peters (00:51)

“Because manual deployments are the number one source of production incidents. Someone forgets the step. Someone copies the wrong file. Someone deploys to the wrong environment. Pipelines eliminate all of that.” – Mirko Peters (08:58)
