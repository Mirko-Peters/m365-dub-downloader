Every licensed user can build in the default environment, yet Microsoft says not to run production work there. This episode explains Power Platform environments, types, Dataverse, roles and governance in plain words for makers and admins. You will know which environment to build in and why.

In this episode

  • 00:00 – Why the default environment is a trap
  • 00:25 – What an environment actually is
  • 02:30 – Environment types
  • 04:53 – Dataverse: one database per environment
  • 05:56 – Roles and access
  • 07:55 – Environment groups and Managed Environments
  • 10:00 – ALM, solutions and data policies
  • 13:40 – Best practices

Key takeaways

  • An app can only reach data sources in its own environment, so many broken connections are boundaries rather than bugs.
  • Use the default environment only for personal experiments, build in developer or sandbox environments and ship managed solutions to production.
  • Maker rights and data access are separate, and data policies, environment groups and Managed Environments add tenant-wide guardrails.

Worth quoting

“An app can only connect to data sources that live in the same environment. If you build an app in one environment and the data sits in another, the app can't see it.” – Mirko Peters (01:59)

“Being allowed to build in an environment isn't the same as being allowed to read its data, and those are two separate doors.” – Mirko Peters (06:16)
