Large language models do not know your company's data and their knowledge is frozen in time. This Simply Explained episode shows developers, architects and IT pros how retrieval-augmented generation on Azure solves that with Azure AI Search, Azure OpenAI and Azure AI Foundry, and how to start building it the right way.

In this episode

  • 01:36 – The two problems LLMs have
  • 03:05 – How retrieval-augmented generation works
  • 04:50 – Azure AI Search: indexing and searching
  • 06:37 – Azure OpenAI and Azure AI Foundry
  • 09:03 – Classic RAG vs. agentic RAG
  • 10:28 – End-to-end example
  • 12:10 – How to start building RAG on Azure

Key takeaways

  • RAG first retrieves relevant content from your own data and passes it to the model with the question, so answers are current and grounded instead of guessed from training memory.
  • On Azure, Azure AI Search indexes and retrieves chunks with vector or hybrid search, Azure OpenAI generates the answer, and Azure AI Foundry wires the agent together.
  • Start with your data, get retrieval right before adding the LLM, and choose agentic RAG only for complex questions where accuracy is worth the extra tokens and latency.
