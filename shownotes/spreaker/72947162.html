Many organizations stop at chatting with AI and never build agents that deliver business value. Mirko Peters and Microsoft MVP Steve Corey walk IT decision-makers, architects and developers through agent anatomy, tool choice from SharePoint agents to Foundry, and the security model that keeps agents from going rogue.

  • 09:09 – Instructions, knowledge and tools
  • 19:10 – Protocols, ecosystems and getting started
  • 25:45 – Real-world example: an intranet agent
  • 33:10 – SharePoint agents, Agent Builder, Copilot Studio or Foundry?
  • 35:50 – Security, permissions and agent harnesses
  • 52:30 – Autonomous and multi-agent future, rapid-fire round

Key takeaways

  • Microsoft 365 Copilot is a generalist, while agents are specialists built from instructions, knowledge and tools to do one job exceptionally well.
  • Secure and govern your data before turning on AI, because agents and Copilot will surface every overshared file.
  • Start with the simplest option, such as a SharePoint agent, and apply least privilege before moving to Copilot Studio, custom engine agents or Foundry.

Worth quoting

“The agent is the opposite of that. It's not designed to do everything under the sun. It's designed to do one thing, and it's designed to do it exceptionally well, because you're going to teach this agent what it needs to know.” – Steve Corey (05:50)

“But really those three things, instructions, knowledge and tools are the core things that make up an agent.” – Steve Corey (11:45)
