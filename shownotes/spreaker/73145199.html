Many apps that sync Microsoft 365 data still download everything every few minutes, wasting bandwidth and hitting rate limits. This episode explains for developers how Microsoft Graph delta queries and delta links work, which limitations to plan for, and how to combine them with change notifications for reliable, efficient sync.

In this episode

  • 00:00 – Why full syncs waste data
  • 01:22 – What is a delta query?
  • 02:50 – How the token system works
  • 04:38 – Limitations you can't ignore
  • 07:25 – Delta query vs. change notifications
  • 09:45 – The hybrid approach
  • 11:42 – Practical rules for production
  • 13:31 – Example: syncing calendar events

Key takeaways

  • A delta query returns only the items added, updated or deleted since your last call, using a saved delta link instead of a full resync.
  • Plan for token expiry after seven days, HTTP 410 resets, processing delays, untracked properties and duplicate changes.
  • Combining change notifications as a trigger with delta queries for the details gives near real-time sync without wasteful polling.

Worth quoting

“A Delta query asks Microsoft Graph for only the changes since your last check. Not everything, just a new, updated, or deleted items.” – Mirko Peters (01:26)

“You don't have to store timestamps or version numbers yourself. You don't have to figure out what changed and what didn't. Microsoft handles all that tracking.” – Mirko Peters (04:27)
