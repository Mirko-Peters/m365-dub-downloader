Most companies have SharePoint documents and AI licenses, yet their AI still comes up empty on specific questions because the data is not connected. This episode is for architects and automation builders who want a private, EU-hosted RAG system. It walks through a complete blueprint with SharePoint, Microsoft Graph, n8n, Mistral OCR and pgvector, including GDPR design and the failure modes to plan for.

In this episode

  • 00:00 – The problem and what RAG really is
  • 03:12 – Why standard search fails
  • 06:26 – The full system architecture
  • 09:34 – Connecting SharePoint via Graph API and credentials
  • 19:38 – File sync logic and routing
  • 25:11 – Mistral OCR, chunking and embeddings
  • 37:14 – Retrieval, re-ranking and agent tools
  • 50:25 – GDPR, failure modes and extensions

Key takeaways

  • RAG quality depends on retrieval rather than the language model, so invest in OCR quality, agentic chunking and re-ranking before upgrading models.
  • Combining Microsoft Graph API calls with n8n's SharePoint module, plus a timestamp-based sync, enables reliable dynamic ingestion of new, changed and deleted files.
  • An agent with vector search, full-document retrieval and SQL tools, hosted on EU infrastructure with Azure OpenAI data zone deployments, answers both semantic and numerical questions in a GDPR-compliant way.

Worth quoting

“The quality of your answer is a direct result of the quality of your retrieval. If you get the retrieval right, even a basic model will perform well.” – Mirko Peters (02:55)

“A system that only uses vector search will always fail on questions that need calculation while a system that only uses SQL will fail on questions that need semantics.” – Mirko Peters (06:05)
