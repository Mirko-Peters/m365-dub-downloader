Large batch jobs often stall because one exact VM size has no capacity when it is needed. This episode is for Azure architects and platform teams running simulations, rendering, testing or data processing at scale. You learn how Azure Compute Fleet, Spot VMs and a retry-safe workload design keep big jobs moving at a controlled cost.

In this episode

  • 00:00 – Why one exact VM size blocks large deployments
  • 00:34 – Compute Fleet in plain English
  • 02:49 – Three choices that give Azure room to work
  • 06:45 – Spot and on-demand VMs
  • 10:07 – Compute Fleet versus virtual machine scale sets
  • 14:03 – Example: an overnight risk calculation
  • 17:26 – When to use it and what to decide first

Key takeaways

  • Azure Compute Fleet lets you request a large pool of capacity across several acceptable VM sizes, zones and pricing models instead of betting a deployment on one exact SKU.
  • Mixing on-demand VMs as a stable baseline with Spot VMs for extra throughput only works when progress lives outside the worker, in durable queues, checkpoints and retry-safe tasks.
  • Virtual machine scale sets fit steady application tiers that serve user traffic, while Compute Fleet fits batch, simulation, rendering and other work that splits across many independent workers.

Worth quoting

“With Compute Fleet, you list multiple acceptable VM sizes. Azure can then place some workers on one size and others on another as long as your workload runs on both.” – Mirko Peters (02:01)

“A Spot VM is not the place for the only copy of an important database, a single user facing server, or a job that loses hours of progress when one worker stops.” – Mirko Peters (07:43)
