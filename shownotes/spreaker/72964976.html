Deploying Azure resources by clicking through the portal is hard to repeat, document and hand off. This episode is for Azure admins, cloud engineers and developers new to infrastructure as code, and explains what Bicep is, how it compares with ARM templates and Terraform, and how to deploy your first file.

In this episode

  • 00:00 – Why clicking around in the portal fails
  • 01:26 – What infrastructure as code means
  • 02:35 – The ARM template problem
  • 04:04 – What Bicep is
  • 06:02 – Bicep versus ARM templates
  • 08:17 – Bicep versus Terraform
  • 09:57 – Getting started with Azure CLI and VS Code
  • 12:15 – Idempotency and where Bicep fits in Azure

Key takeaways

  • Infrastructure as code replaces manual portal deployments with declarative, version-controlled files that produce the same result every time they run.
  • Bicep compiles to ARM JSON and uses the same Azure Resource Manager engine, but needs roughly half the code, infers dependencies automatically and adds modules and what-if previews.
  • For Azure-focused teams Bicep avoids Terraform's state file and supports new Azure features on day one; getting started only takes the Azure CLI and the Bicep extension for VS Code.

Worth quoting

“Here's the thing, clicking around works for learning. It fails for production. So what's the alternative? You write a file that describes what you want, then you tell Azure to build it.” – Mirko Peters (01:24)

“That's an important distinction. Infrastructure as code is the concept. Bicep is just one tool that implements it.” – Mirko Peters (02:29)
