Many factories stream machine data to the cloud and build live dashboards, yet a stopped line still ends with someone calling the planner. This episode is for manufacturing, OT and data architects who want to connect a machine fault to a changed production decision. It walks through the full pipeline from edge and event transport through Fabric Real-Time Intelligence, context, APS and governed write-back.

In this episode

  • 00:00 – Why Excel still sits between alarm and action
  • 04:33 – Capture, interpret, decide, act
  • 09:34 – From the edge to meaningful events
  • 24:44 – Fabric Real-Time Intelligence, Eventhouse and KQL
  • 44:42 – Shared data model, digital twin and knowledge graph
  • 64:37 – Copilot explains, APS tests feasible plans
  • 73:40 – The line three scenario and what an event does not know
  • 94:40 – Closing the loop, Activator and decision quality

Key takeaways

  • A machine event is a fact, not a decision: value only appears when it changes a named decision with a clear owner in time.
  • Shared asset identities, data contracts and context joins to MES, ERP and planning data must come before AI or automated escalation.
  • Use Fabric Real-Time Intelligence and Activator for awareness and tracked workflows, APS for feasible plans, and keep machine control local and safe.

Worth quoting

“A temperature reading, a fault code, or a machine stop does not create value just because it entered a cloud platform. It creates value when it changes a named decision in time for that decision to matter.” – Mirko Peters (83:25)

“If those names don't resolve to a single approved asset identity, any AI system will get four partial stories about one physical machine. That's not an AI problem, it's a data model problem” – Mirko Peters (45:07)
