Azure Blob Storage is probably the cloud storage service you use most without knowing it. This episode explains the account-container-blob hierarchy, blob types, access tiers, lifecycle rules, security and redundancy for Azure beginners, so they can store unstructured data safely and cheaply.

  • 00:57 – What is Blob Storage?
  • 02:47 – Storage account, container, blob
  • 04:40 – Block, append and page blobs
  • 06:22 – Hot, cool, cold and archive tiers
  • 08:39 – Lifecycle management
  • 10:49 – Security and access control
  • 13:41 – Redundancy and real-world use cases

Key takeaways

  • Blob Storage is flat object storage for unstructured data, organized as storage account, container and blob.
  • Block, append and page blobs serve files, logs and VM disks, while hot, cool, cold and archive tiers trade storage cost against access cost, automated by lifecycle management rules.
  • Prefer Microsoft Entra ID with Azure RBAC over account keys and SAS tokens, and choose LRS, ZRS or GZRS based on how critical the data is.

Worth quoting

“Unstructured data is anything that doesn't fit neatly into rows and columns. A photo of your dog, a product demo video, a web server, log file, a database backup, a PDF contract.” – Mirko Peters (01:07)

“If it's a file someone uploads or downloads, use a block blob. If it's a continuous stream of log entries or sensor readings, use an append blob. If it's a virtual machine disk, use a page blob” – Mirko Peters (06:10)
