Clicking through admin portals does not scale across Microsoft 365 and Azure. Automation architect Matthew Dowst shows admins and engineers how to use PowerShell and Microsoft Graph to build automation that can restart, report and scale, and why PowerShell gets more powerful as everything moves to APIs.

In this episode

  • 03:57 – Graph modules, wrappers and direct API calls
  • 08:41 – Copilot, Power Automate and what the GUI cannot do
  • 14:13 – Costs, reporting across tenants and the Log4j story
  • 22:07 – Automate everything? Patterns of advanced scripting
  • 27:39 – Common automation mistakes and testing against changing tenants
  • 33:58 – The future of PowerShell and advice for new admins
  • 37:08 – Hot takes and final advice

Key takeaways

  • PowerShell is both an admin tool and a workflow automation tool, and the Microsoft Graph modules have standardized how it works across Microsoft 365 and Azure.
  • Build automation that can restart safely: create objects with the minimum required data, set attributes step by step and capture errors instead of silencing them.
  • Power Automate and GUIs complement PowerShell, but enterprise-scale work needs the control, logging and repeatability that scripts and APIs provide.
