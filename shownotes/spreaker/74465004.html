When stock levels live in a warehouse system and invoices in finance, copying everything into Dynamics 365 creates stale numbers, duplicates and fragile sync jobs. This Simply Explained episode helps Dynamics 365 and Power Platform makers, admins and architects understand virtual tables, formerly virtual entities. Learn how providers and data sources work, where virtual tables fit, and when a local copy is still the better choice.

Key takeaways

  • Dataverse virtual tables, formerly virtual entities, show live external data in Dynamics 365 without storing a second copy, so the source system keeps ownership.
  • Every virtual table relies on a data provider that translates requests, a data source that points to the external service, and a table definition that maps columns and GUID IDs.
  • Virtual tables don't support Dataverse auditing, search, charts, offline use or calculated columns, depend on the source for security and speed, and can't be converted later, so choose deliberately.
