## Key takeaways

- Prompt engineering alone is not enough: organizations still need architects and specialists who understand the customer, the data and the underlying technologies.
- Yves recommends a multi-agent approach with clearly scoped agents, Copilot Studio for low-code needs and custom development when the orchestration or models must be customized.

## FAQ

**When should you use Copilot Studio instead of custom code for agents?**

Use Copilot Studio when you do not need to customize the orchestrator. It lets makers define instructions, tools, MCP servers and knowledge sources quickly. Yves moves to custom development, for example with Semantic Kernel or the Agent Framework, when the orchestration or plan must be controlled, or when models outside Microsoft's catalog are required.

**Does an MCP server replace existing APIs?**

No, an MCP server sits in front of existing APIs and works with them behind the scenes. It gives the AI context by exposing available tools, descriptions and skills, while the actual calls still go to APIs, databases or other services. Builders still have to handle each API's authentication behind the MCP server.

**Should Copilot agents use delegated or application permissions?**

Yves recommends delegated user permissions by default, because the user then only reaches data and tools they already have access to. If application permissions are needed for a specific API, wrap them, for example inside an MCP server, so the user calls the wrapper with their own permissions and never touches application permissions directly.
