## Key takeaways

- Enterprises learn AI governance fastest by building small solutions while steadily improving DLP policies, sensitivity labels and monitoring rather than waiting for a perfect model.
- Good RAG depends on good data: well-described metadata, a clean production knowledge base without outdated versions, and careful chunking keep answers accurate and token costs down.
- Production agents need clearly communicated tasks, tightly scoped connectors, manual testing and the right model size, because small language models are often enough and endless agent loops can become expensive.

## FAQ

**How should you set up DLP for Copilot Studio agents?**

Keep each agent's connector scope as small as its use case. Elliot Margot uses Power Platform DLP policies per environment, so an agent that summarises your day only gets Teams and Outlook, and a new use case gets its own environment and policy. Microsoft Purview sensitivity labels keep confidential documents, such as HR files, away from agents.

**Why does metadata matter for RAG in Copilot Studio?**

Metadata helps the agent find the right document quickly and use fewer tokens. Elliot Margot suggests adding columns such as description and language to SharePoint knowledge sources, so a Chinese question reaches the Chinese document directly. He also keeps old versions out of the production knowledge base, because duplicates raise both risk and token costs.

**How can you keep Copilot Studio agent costs under control?**

Choose the smallest model that does the job and never tell an agent to keep trying until it finishes. Elliot Margot describes waking up to a large bill after an agent kept looping on a task. He recommends letting agents stop and notify you when stuck, and using small models such as GPT-4.1 for simple summaries.
