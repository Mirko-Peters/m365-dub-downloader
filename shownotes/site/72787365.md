## FAQ

**What are Azure deployment stacks in Bicep?**

A deployment stack is an Azure resource that wraps a Bicep template and keeps a record of the resources it owns. When a resource disappears from the template, the stack can delete it, detach it or leave it alone. Deny settings can block changes made outside the pipeline, bringing a Terraform-like state model natively to Azure.

**Should I use Bicep or Terraform for Azure?**

If Azure is your cloud, Bicep is probably the right choice; if you manage several clouds, Terraform probably is. The episode explains that Bicep supports new Azure features immediately and needs no separate state file, while Terraform offers one workflow across providers but requires carefully protected state. Azure Verified Modules exist for both.

**Why deploy Bicep at management group scope?**

Deploying at management group scope lets you define governance once and have it cascade to every subscription below. Policy definitions, initiatives and role assignments set there are inherited automatically, so a new subscription is compliant from the start. Because it needs elevated permissions, governance changes become deliberate, reviewed and auditable rather than casual.
