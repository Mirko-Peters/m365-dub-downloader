## Key takeaways

- OneLake is a single logical data lake per tenant, built on Azure Data Lake Storage Gen2 and delivered as a SaaS service, where every [Fabric](https://www.m365.fm/entity/fabric/?utm_source=podcast&utm_medium=shownotes&utm_campaign=microsoft-fabric-onelake-simply-explained) workload stores its data in open Delta Parquet format.
- The OneCopy principle lets Spark, SQL and [Power BI](https://www.m365.fm/entity/power-bi/?utm_source=podcast&utm_medium=shownotes&utm_campaign=microsoft-fabric-onelake-simply-explained) read the same physical data, while shortcuts reference external data in place and mirroring replicates databases in near real time without pipelines.
- Lakehouse, Warehouse and Eventhouse are different views over the same storage, governed by one security model with workspace roles, OneLake security roles, the OneLake catalog and Purview integration.

## FAQ

**What is the difference between OneLake shortcuts and mirroring in Microsoft Fabric?**

Shortcuts point to data where it lives without copying it, while mirroring copies database data into OneLake and keeps it updated in near real time. Shortcut query speed depends on the source, such as an S3 bucket. Mirrored data sits in OneLake as Delta Parquet, so queries are fast but you store a copy.

**Is OneLake the same as Azure Data Lake Storage Gen2?**

No, OneLake is built on Azure Data Lake Storage Gen2 but delivered as a SaaS service. With ADLS Gen2 you create storage accounts, manage containers and set up access keys yourself. OneLake removes that work, gives each tenant one logical lake and stores data in the open Delta Parquet format by default.

**Should I use a Lakehouse, Warehouse or Eventhouse in Microsoft Fabric?**

You usually use all three, because each solves a different problem over the same OneLake storage. The Lakehouse suits data engineering and raw files, the Warehouse offers full T-SQL for BI reporting, and the Eventhouse handles streaming data queried with KQL. Tables in one can be read from the others.
