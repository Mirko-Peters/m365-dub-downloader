## Key takeaways

- Autonomous agents need tighter identity boundaries than humans: replace long-lived service principal tokens with just-in-time, task-scoped tokens from a policy engine, managed identities and continuous access evaluation.

## FAQ

**How does Semantic Kernel turn PowerShell scripts into an AI agent?**

Semantic Kernel acts as an orchestration engine between a language model and your tools. You wrap the needed cmdlets in single-purpose .NET methods, mark them with kernel function and description attributes, and register them as a plugin. The model reads the descriptions and decides when, and in which order, to call each function.

**Why are long-lived service principal tokens risky for autonomous agents?**

A token issued at the start of a script stays valid for the whole run, often with broad tenant-wide permissions. If the script is compromised, an attacker inherits all of them. The episode recommends just-in-time tokens from a policy engine, scoped to one task and valid for seconds, plus managed identities and continuous access evaluation.

**Which IT tasks should an agent handle without human approval?**

Read-only, low-risk actions such as listing users, checking forwarding rules or reading device compliance can run autonomously. Changes like deleting accounts, resetting MFA, altering permissions or Conditional Access policies should go to a human as a structured proposal, for example a Teams adaptive card with approve, reject and question options.
