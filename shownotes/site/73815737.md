## FAQ

**When should you still use a plug-in instead of Power Automate in Dynamics 365?**

Use a plug-in when a rule must run inside the Dataverse transaction, such as blocking a record from saving with invalid or missing legal data. Code also fits performance-sensitive, high-volume work and reusable components like PCF controls or custom connectors. Keep each plug-in narrow, doing one defined job, and move orchestration into Power Platform.

**Why shouldn't business-critical Power Automate flows run under a personal account?**

A flow owned by one employee can stop working when that person changes roles, loses access or leaves the company. Sharing a flow does not change its primary owner. For unattended automation, use an identity that matches the process, such as a purpose-built service account with named owners, proper licensing, reviewed permissions and limited access.

**How do you start migrating custom Dynamics code to Power Platform?**

Start with an inventory, not a rewrite. List every plug-in, script, classic workflow, integration and flow, then record its owner, trigger, fields, dependencies and execution mode. Begin with a process that changes often and crosses systems, build it in a solution, run it in parallel with the old automation and retire the code only after proof.
