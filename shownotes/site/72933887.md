## Key takeaways

- Scout is Microsoft's first Autopilot: unlike Copilot and Cowork, it acts proactively on schedules and triggers without waiting for a prompt.
- Scout runs as a desktop app under its own identity, connects to Microsoft 365 via Work IQ, local files, the web and [MCP](https://www.m365.fm/entity/mcp/?utm_source=podcast&utm_medium=shownotes&utm_campaign=microsoft-scout-simply-explained) servers, and gates sensitive actions with approvals.
- Scout is in private Frontier preview and needs Microsoft 365 Copilot, a GitHub Copilot license and [Intune](https://www.m365.fm/entity/intune/?utm_source=podcast&utm_medium=shownotes&utm_campaign=microsoft-scout-simply-explained) policies, so organizations should start with Copilot, Cowork skills and agent governance now.

## FAQ

**What is the difference between Microsoft Scout and Copilot?**

Copilot waits for you to start a conversation and acts with your identity, while Scout acts on its own schedules and triggers under its own identity. Scout keeps running in the background even when the chat is closed, so it can prepare briefs, flag urgent emails or track overdue decisions without being prompted each time.

**What licenses do you need to use Microsoft Scout?**

You need a Microsoft 365 Copilot license, a GitHub Copilot Business or Enterprise license and an organization enrolled in the Frontier preview. An IT admin must also configure Intune policies to allow Scout on the device. Scout's usage is billed through GitHub Copilot credits, which makes it a separate budget line from Microsoft 365 Copilot.

**How does Scout stay safe when it acts on its own?**

Scout gates sensitive actions behind an approvals model and logs everything it does under its own identity. Before sending an email, deleting a file, opening a browser or running a command it asks you to allow once, allow for the session or deny. Administrators can audit what Scout did, when it did it and which data it accessed.
