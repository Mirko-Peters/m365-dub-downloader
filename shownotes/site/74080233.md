## Key takeaways

- Microsoft Entra Connect is the controlled bridge that syncs selected users, groups and details from on-premises Active Directory to Microsoft Entra ID, with Active Directory remaining the source of authority.
- Password hash synchronization fits most organizations, pass-through authentication keeps the local directory in every password check, and federation suits existing sign-in systems.
- Entra Connect Health warns when sync stops, which matters most when disabled accounts must also lose cloud access, and Entra Connect is neither a backup nor a replacement for MFA or [conditional access](https://www.m365.fm/entity/conditional-access/?utm_source=podcast&utm_medium=shownotes&utm_campaign=microsoft-entra-connect).

## FAQ

**What does Microsoft Entra Connect do?**

Microsoft Entra Connect links on-premises Active Directory with Microsoft Entra ID so one employee has one connected identity. It syncs selected users, groups and details to the cloud, typically checking for changes about every 30 minutes, supports a chosen sign-in method, and Entra Connect Health warns IT when the connection stops working.

**Does Entra Connect assign Microsoft 365 licenses or create mailboxes?**

No, Entra Connect only brings the identity across to Microsoft Entra ID. Assigning a Microsoft 365 license is a separate task, and Exchange Online uses that license to create the mailbox. The episode notes this often confuses people who expect a mailbox to appear the moment a synced user shows up in the cloud.

**Should I use password hash synchronization or pass-through authentication?**

Password hash synchronization fits most organizations, because Microsoft Entra ID checks sign-ins in the cloud and users can often still reach Microsoft 365 if local servers fail. Pass-through authentication suits companies that need local Active Directory to check every password, but its agents must stay available. Federation fits companies with an existing sign-in system.
