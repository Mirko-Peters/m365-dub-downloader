## Key takeaways

- An API gateway gives clients one front door to many backend services and hides where those services live.
- Routing, authentication, rate limiting, load balancing and data transformation run in one pipeline with central visibility.
- Once you have three or more services or external API consumers, start by centralizing authentication at the gateway, then add rate limiting.

## FAQ

**When do you need an API gateway?**

Once you have three or more services or expose APIs to external clients. With one or two services you can usually handle routing and authentication in each service yourself. Beyond that, complexity grows fast and a gateway pays for itself by giving clients one URL and centralizing security, rate limiting and visibility.

**What is the difference between Azure API Management and an API gateway?**

Azure API Management is the full platform, and the gateway is its core component that handles traffic. Besides the gateway, Azure API Management adds management features, a developer portal and analytics. The episode stresses that the pattern matters more than the tool: a single entry point, centralized policies and observability.

**What should you move behind an API gateway first?**

Centralize authentication first. Pick one service and move its auth check to the gateway, so token validation logic no longer lives in every service. Next, add rate limiting, for example a basic limit of a hundred requests per minute per client, and finally route all services through one URL.
