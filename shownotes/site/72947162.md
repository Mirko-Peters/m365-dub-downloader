## FAQ

**What is the difference between Microsoft 365 Copilot and a Copilot agent?**

Microsoft 365 Copilot is a generalist assistant, while an agent is a specialist built to do one task exceptionally well. Steve Corey describes Copilot as a jack of all trades. An agent gets long, detailed instructions, often using most of the roughly 8,000 available characters, so it focuses only on its single job.

**Should I build a Copilot agent in SharePoint, Agent Builder, Copilot Studio or Foundry?**

Start with the simplest option, usually a SharePoint agent, and only move up when you need more capabilities. Agent Builder adds tools, Copilot Studio adds complexity and Power Platform considerations, and Foundry means hosting models yourself. Starting every agent in Foundry creates technical debt, higher maintenance costs and fewer Microsoft 365 Copilot benefits.

**How do I stop a Copilot agent from deleting data or going rogue?**

Apply the least privilege principle so an agent can do exactly what it needs and nothing more. Many horror stories involve agent harnesses rather than single agents. Agents often run with the user's permissions, and Agent 365 adds a governance layer that can block actions, so question every Microsoft Graph permission a developer requests.
