Many IT leaders trust Microsoft 365's native versioning and redundancy to save them from ransomware, but synchronized corruption and a shared identity perimeter can wipe out production and backups together. This episode is for architects, security and compliance leads who own business continuity. You will learn how to design an isolated, immutable backup vault with its own identity boundary, and why it can also cost less.

## Key takeaways

- Native Microsoft 365 versioning and geo-redundancy protect against hardware failure, not against ransomware that abuses legitimate APIs and privileged roles.
- A backup that authenticates against the production [Entra ID](https://www.m365.fm/entity/entra-id/?utm_source=podcast&utm_medium=shownotes&utm_campaign=m365-backup-isnt-enough-the-case-for-isolated-vault-architecture) tenant shares its blast radius; true isolation needs a separate recovery tenant with immutable WORM storage and multi-party approval.
- Regulations such as SEC Rule 17a-4, NIS2 and DORA, plus the storage costs of native backup, make an isolated third-party vault both a compliance and an economic decision.

## FAQ

**Is Microsoft 365 version history enough to recover from ransomware?**

No, version history is not a separate copy of your data but a file attribute stored alongside the file. An attacker with the right permissions can make 501 sequential edits to push the clean version out of the 500-version limit, and the Graph API lets automated scripts repeat this across thousands of files very quickly.

**Why should a Microsoft 365 backup use a separate identity tenant?**

A backup that authenticates against the production Entra ID tenant shares its blast radius. If a global admin account or privileged token is stolen, the attacker can simply log in and switch off immutability. The episode recommends a secondary recovery tenant with no federation, no user synchronization and no trust relationship to production.

**Is native Microsoft 365 backup storage more expensive than an isolated vault?**

According to the episode, often yes. Mirko cites 15 cents per gigabyte per month for native storage versus about 0.0068 dollars per gigabyte at an object storage provider like Wasabi, at the time of recording. For a 10,000-user organization with two petabytes, he estimates $300,000 per year in Azure charges for the native model.
