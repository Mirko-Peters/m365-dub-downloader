## Key takeaways

- Microsoft Security Copilot is an AI layer on top of Defender, Entra, Intune and Purview that triages alerts, summarizes incidents and recommends actions using your own tenant data.
- Pre-built agents such as phishing triage and [conditional access](https://www.m365.fm/entity/conditional-access/?utm_source=podcast&utm_medium=shownotes&utm_campaign=microsoft-security-copilot-simply-explained) optimization do the repetitive work, while humans still approve the actions.
- Microsoft 365 E5 includes a monthly allotment of Security Compute Units, but you should audit permissions and oversharing before enabling it and start with a single agent.

## FAQ

**How many Security Compute Units come with Microsoft 365 E5 for Security Copilot?**

E5 includes 400 Security Compute Units per month for every 1,000 users, according to the episode. A 50-user company gets about 20 SCUs, 200 users get 80, and the allotment caps at 10,000 SCUs around 25,000 users. The units land in a shared pool automatically, and extra SCUs can be bought if needed.

**What happens when Security Copilot runs out of SCUs?**

It simply stops working until the next monthly allotment refreshes, because overage is disabled by default. That means no surprise bills unless you deliberately switch overage on. The episode recommends leaving it off while testing, deleting provisioned SCUs afterwards, and notes that workspace data is kept for 90 days after deletion.

**Does Security Copilot copy or store my security data?**

No, it queries connected systems such as Defender, Entra, Intune and Sentinel in real time through plugins, so data stays inside your tenant. Microsoft states customer data is not used to train foundation models. The real risk is broad permissions, since Copilot can surface anything the prompting user can already access.
