## Key takeaways

- Microsoft Entra External ID is Microsoft's CIAM service for customers, partners and guests and replaces Azure AD B2C, swapping XML custom policies for user flows and custom authentication extensions.
- It covers customer sign-up (B2C), partner collaboration (B2B) and machine-to-machine scenarios, and customer-facing apps should usually run in a separate external tenant rather than the workforce tenant.
- B2C stays supported until at least 2030 but gets no new features, so new projects should start on External ID and existing B2C tenants should plan a step-by-step migration.

## FAQ

**What is the difference between Azure AD B2C and Microsoft Entra External ID?**

Microsoft Entra External ID is the successor to Azure AD B2C, unified under the Entra brand. Instead of long XML custom policies, you configure user flows in the admin center or use custom authentication extensions. B2C stays supported until at least 2030, but new features such as passkeys and native authentication arrive only in External ID.

**Should customers live in a workforce tenant or an external tenant?**

For a customer-facing app with thousands of users, use a separate external tenant. It keeps customer data apart from employees, allows separate branding, offers a native authentication API for mobile apps and uses monthly active user pricing. A workforce tenant with guest self-service sign-up is fine for inviting a handful of partners to internal resources.

**How do I migrate from Azure AD B2C to Microsoft Entra External ID?**

Migrate one application first, test it, learn from it, then move the rest. Tenants under about 5 million directory objects use a tenant-to-tenant move with bulk user export and import and just-in-time password migration. Larger tenants can use high scale compatibility mode, and XML custom policies must be rebuilt by hand.
