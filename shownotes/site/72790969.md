## FAQ

**Why do standard Azure landing zones fail for AI workloads?**

Standard landing zones assume static resources with predictable access patterns, while LLM workloads pull data from many sources and change constantly. When teams deploy Azure OpenAI manually in the portal, each uses different identities, network settings and logging, which creates configuration drift, invisible token spend and gaps that auditors find quickly.

**What do auditors ask about AI infrastructure on Azure?**

Auditors ask to see the code that deployed the resource, who has access to the endpoint, how data flows from the knowledge base to the model, how token costs are attributed, and whether the setup can be replicated in another region. Bicep modules and commit history answer these; portal deployments usually cannot.

**How does Azure API Management help control Azure OpenAI costs?**

Azure API Management sits between clients and Azure OpenAI as a gateway, so every request is authenticated, rate-limited and logged. Products and subscriptions map to teams with their own token quotas, and policies emit token metrics to Application Insights, letting you attribute spend by feature, team or business unit instead of waiting for the invoice.
