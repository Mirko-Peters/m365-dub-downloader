- Azure IoT Hub uses MQTT as a managed device connection with per-device identity, fixed topics, QoS 0 or 1 and routing, so it complements rather than replaces a local MQTT broker.

## FAQ

**Is Azure IoT Hub a full MQTT broker?**

No. Azure IoT Hub uses MQTT 3.1.1 as a managed device connection, not a general broker. It enforces fixed topic patterns, one active connection per device identity, up to five subscriptions and no persisted retained messages. For flexible plant-side publish and subscribe, run a local broker and forward selected messages to IoT Hub.

**Which MQTT QoS levels does Azure IoT Hub support for device telemetry?**

Azure IoT Hub supports QoS 0 and QoS 1, and it closes the connection if a device publishes with QoS 2. QoS 0 can lose a message, which may suit frequent samples. QoS 1 retries until acknowledged, so fault events can arrive twice, and downstream consumers must handle duplicates without opening a second ticket.

**Which ports does an MQTT connection to Azure IoT Hub use?**

MQTT to Azure IoT Hub runs over TLS on port 8883, or over WebSockets on port 443 when firewalls block 8883. Unsecured traffic on port 1883 is not accepted. In a plant, map DNS resolution, firewalls, outbound proxies and rule ownership before deployment, because network problems often look like a broken MQTT client.
