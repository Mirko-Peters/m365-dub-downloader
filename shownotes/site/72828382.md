## Key takeaways

- Generative pages let you keep the out-of-the-box strengths of a model-driven app and extend only the UI where it falls short.
- For production-ready generative pages, build them through a coding tool such as VS Code with [GitHub Copilot](https://www.m365.fm/entity/github-copilot/?utm_source=podcast&utm_medium=shownotes&utm_campaign=beyond-prompt-a-page-building-enterprise-ready-ai-experiences-in-power-apps-with-sara-lagerquist) and Microsoft's skill rather than the maker portal, which is best for trying things out.

## FAQ

**Should I build generative pages in the maker portal or in VS Code?**

Use a coding tool such as VS Code with GitHub Copilot for anything solid. Sara Lagerquist sees the maker portal mainly for trying things out or a proof of concept, since it regenerates the whole page on each prompt and offers limited model choice outside some countries. Microsoft's generative pages skill adds planning and wireframes.

**When does a generative page make sense in a model-driven app?**

A generative page fits when the standard model-driven UI is not enough but the data and users still belong to that app. Sara mentions multi-table wizards, kanban or scheduling boards, calendars and bulk record creation, for example many-to-many relationships that would otherwise take five or six clicks per record.

**Should I still install the Power Platform CoE Starter Kit?**

Sara would not implement it now. She understands Microsoft has stopped developing the Center of Excellence kit because the Power Platform admin center now covers most of its governance features. If you already use the kit, keep it while it helps, but check which parts the admin center has made redundant.
