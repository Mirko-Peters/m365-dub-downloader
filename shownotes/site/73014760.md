Servers spread across your data center, Azure, AWS and Google Cloud, each with its own console? This episode explains Azure Arc in plain English for IT admins managing hybrid and multi-cloud estates, showing how one control plane brings governance, security, monitoring and patching to every server.

## Key takeaways

- Azure Arc is not a cloud and moves nothing; it projects servers, Kubernetes clusters and SQL Server instances outside Azure into Azure Resource Manager.
- The free Connected Machine agent connects outbound over HTTPS, so Azure Policy, RBAC, tags, Defender for Cloud, Sentinel, Azure Monitor and Update Manager work the same on-premises, in AWS and in GCP.
- Start small: register the resource providers, onboard one test server with the generated script, then add policy, Defender and update management step by step.

## FAQ

**Does Azure Arc cost money to use?**

Connecting a server to Azure Arc is free, because the Connected Machine agent costs nothing. You only pay for the services you enable on top, such as Microsoft Defender for Cloud, Azure Update Manager or Azure Monitor. The episode also mentions pay-as-you-go licensing for Arc-enabled SQL Server, billed per core per hour.

**Does Azure Arc require a VPN or inbound firewall ports?**

No. The Connected Machine agent connects outbound to Azure over HTTPS on port 443, so you do not need inbound ports or a VPN. Monitoring data, scripts and browser-based management through Windows Admin Center all travel over this secure outbound channel, which helps with remote or locked-down servers.

**Do Azure virtual machines need Azure Arc?**

No. Native Azure VMs already include the Azure VM agent, which provides the same management capabilities, so Arc is only for machines outside Azure. That includes servers in your own data center, at branch offices or the edge, and in other clouds such as AWS and Google Cloud, plus Kubernetes clusters and SQL Server.
