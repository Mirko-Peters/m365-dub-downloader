## Key takeaways

- Service principals were built for static applications and cannot handle instancing, credential sprawl, per-agent logging or lifecycle governance for AI agents.
- Microsoft Entra Agent ID makes agents first-class identities with blueprints that centralize credentials, mandatory human sponsors, access reviews, conditional access and agent-specific risk detection.
- Organizations should inventory existing agents, assign sponsors, build blueprints and harden them with conditional access, [Purview](https://www.m365.fm/entity/purview/?utm_source=podcast&utm_medium=shownotes&utm_campaign=your-ai-agents-are-orphaned-the-structural-shift-to-agent-id) and Defender before auditors or incidents force the issue.

## FAQ

**Why are service principals a poor fit for AI agents?**

Service principals were designed for static, long-lived applications with a one-to-one link to an app registration. They have no instancing, so many agent instances end up sharing one identity or need separate registrations, every identity needs its own credential, logs cannot tell instances apart, and nothing expires when an agent's purpose ends.

**What is an Agent ID blueprint in Microsoft Entra?**

A blueprint is a reusable template that defines what an agent is, which roles and Microsoft Graph scopes it gets, and how it authenticates. It can spawn many agent identities, each with its own object ID in the logs. The blueprint holds the credential and performs a token exchange, so individual agents hold no secrets.

**How much does Microsoft Agent 365 cost?**

At the time of recording, Agent 365 standalone costs 15 dollars per user per month, while the Microsoft 365 E7 bundle, which includes E5, Copilot and Agent 365, costs 99 dollars. It is licensed per governing user, not per agent, and AI runtime such as Copilot credits or Azure tokens is billed separately.
