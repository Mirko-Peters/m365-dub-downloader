## Key takeaways

- Rolling out Copilot safely starts with permission hygiene and Purview guardrails, because Copilot surfaces any data a user already has access to.
- Copilot extensibility spans SharePoint agents, Agent Builder, Copilot Studio, the Agents Toolkit and Microsoft Foundry, and the right choice depends on the use case.

## FAQ

**What should an organization do before rolling out Microsoft 365 Copilot?**

Fix permissions and put Purview guardrails in place before switching Copilot on. Copilot surfaces any data a user can already access, so oversharing at site, library, folder or file level becomes a leak risk. Reshmee uses PnP PowerShell scripts to inventory permissions and recommends a readiness workshop to see where the tenant stands.

**Why build several specialized agents instead of one agent that does everything?**

Smaller agents with a subset of tools, knowledge and instructions perform better and are easier to test and maintain. One agent covering IT, sales and marketing struggles to pick the right tool, especially when tools have similar names. An orchestrator or parent agent routes user intent to the right connected agent, which can be swapped out easily.

**What is the difference between using MCP and calling APIs directly in an agent?**

MCP acts as a wrapper around APIs and exposes many ready-made tools, so developers avoid building a separate custom connector for each API. The downside is noise: one MCP server may expose 10 to 30 tools. Reshmee advises enabling only the tools an agent needs, such as sending email but not deleting it.
