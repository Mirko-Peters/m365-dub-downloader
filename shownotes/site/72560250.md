## FAQ

**Why shouldn't AI agents run under service principals?**

Service principals were built for static, predictable workloads, while agents decide at runtime which tools and systems to use. Teams therefore grant every permission an agent might need, creating over-privileged God accounts. The audit log then shows only a service principal ID and a timestamp, not which agent acted, who owns it or why.

**What is an agent identity blueprint in Microsoft Entra?**

An agent identity blueprint is a reusable template that sets policy for a category of agents. It defines credentials, permission baselines, approval requirements and lifespan, and every agent built from it inherits those rules. The episode recommends three to five initial blueprints across low, medium and high risk tiers, updated centrally instead of per agent.

**How do you find shadow AI agents in your organization?**

Start with an inventory across Copilot Studio, Azure, AWS, Google and Salesforce, look for API usage patterns, and interview teams. Then triage each agent by purpose, owner, data access, usage and controls into green, yellow or red. Red agents without owners or controls are disabled first and investigated afterwards, and discovery runs continuously.
