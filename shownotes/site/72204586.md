This episode shows architects and Power Platform developers how Dataverse elastic tables, hierarchical partition keys and layered security make scalable, audit-ready SaaS on Power Pages possible, and where the approach stops being the right choice.

## Key takeaways

- Use standard Dataverse tables for core relational business entities and elastic tables, backed by [Azure Cosmos DB](https://www.m365.fm/entity/cosmos-db/?utm_source=podcast&utm_medium=shownotes&utm_campaign=breaking-the-scale-barrier-building-multi-tenant-saas-on-power-pages), for high-volume operational data such as logs, telemetry and audit events.
- Choose the partition key up front, ideally a hierarchical key with tenant ID at level one, and include it in every query to keep performance and tenant isolation intact.
- Layer tenant isolation across Cosmos DB partitions, Dataverse business units and Power Pages table permissions, and push bulk ingestion to back-end services using CreateMultiple.

## FAQ

**When should I use Dataverse elastic tables instead of standard tables?**

Use elastic tables for high-volume, append-heavy data such as logs, telemetry, audit events and activity feeds. Bulk operations with CreateMultiple run two to ten times faster in community tests, but single-record CRUD is no faster and standard OData retrieval is slower. Keep relational core business entities in standard tables.

**How do hierarchical partition keys solve the elephant tenant problem?**

They spread one large tenant across many sub-partitions. Instead of tenant ID alone, you define up to three levels, such as tenant ID, user ID and item ID. No single logical partition hits the 20 GB limit, while tenant-scoped queries still route efficiently. The keys must be set when the container is created.

**How much cheaper is elastic table storage than standard Dataverse storage?**

At the time of recording, roughly 75 percent cheaper: about $10 per GB per month on log capacity versus about $40 for database capacity. Each tenant only gets 2 GB of log storage by default, so you need log capacity add-ons to keep that price. TTL-based automatic deletion keeps storage bounded.
