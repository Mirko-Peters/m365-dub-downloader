## FAQ

**Why doesn't Conditional Access protect AI agents that run as a user?**

Conditional Access cannot govern an agent it cannot identify, so an agent running with a human's credentials looks like that person signing in. Giving each agent its own Microsoft Entra Agent ID lets you apply conditional access per agent type, flag risky behavior, quarantine one identity and disable it without disabling the employee it borrowed.

**Should AI agents use delegated Microsoft Graph permissions or app roles?**

App roles with resource scoping are the safer choice, because delegated permissions turn the agent into the user it borrowed. Grant site-scoped SharePoint access to named sites and specific shared mailboxes instead of tenant-wide reads. If an exception truly needs broad access, give it an expiry and log every call it makes.

**How can you score the risk of AI agents in Microsoft 365?**

Score each agent from zero to five on six inputs: identity, data, permissions, network, monitoring and life cycle, then add the results. Points come from controls such as Entra Agent ID, Purview labels, app roles, Global Secure Access and automated deprovisioning. Run it on your top ten agents and show each score in the agent registry.
