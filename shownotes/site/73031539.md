## Key takeaways

- An Azure Storage account is one container that holds four services: Blob for unstructured files, Files for network shares, Queue for messages and Table for simple structured data.
- Choose Standard performance for most workloads and pick redundancy (LRS, ZRS, GRS) based on how much downtime and data loss you can tolerate.
- The services are designed to work together under one account with shared billing, security, encryption and networking, so you can start small and add services later.

## FAQ

**What is an Azure Storage account?**

An Azure Storage account is a container that holds Azure's storage services together: Blob, Files, Queue and Table. It needs a globally unique name, lives in a chosen region and belongs to a resource group. Once created, you can use any or all four services inside it without being locked into one.

**What is the difference between Azure Queue storage and Azure Service Bus?**

Queue storage is the simpler, cheaper option built into the storage account, while Service Bus is a separate service with advanced features. Service Bus adds transactions, sessions, messages up to 100 megabytes and guaranteed first-in, first-out ordering. Queue storage messages are limited to 64 kilobytes, delivered at least once, and suit most background processing scenarios.

**When should I use Azure Table storage instead of Cosmos DB?**

Use Table storage when you need cheap storage for large amounts of structured data with simple key-value lookups. It is schemaless and fast when you query by partition key and row key. It does not support complex queries, indexing or stored procedures, so workloads needing those belong in a fuller database like Cosmos DB.
