## FAQ

**Should I use the Microsoft Graph PowerShell modules or call the Graph API directly?**

Use the Graph PowerShell modules when you control the environment, and direct API calls when you deliver scripts elsewhere. Modules are easier for others to read and handle paging and timeouts for you. Calling the API directly gives tight control over which version is used, but makes long-term maintenance harder because you must track API changes.

**What is the most common mistake in PowerShell automation for Microsoft 365?**

The most common mistake is automation that cannot be restarted safely. Matthew Dowst recommends creating objects such as users with only the minimum required data, then setting attributes step by step, checking whether things already exist, and recording errors instead of silencing them, so one failed attribute does not stop or break the whole run.

**Is Power Automate replacing PowerShell?**

No, Power Automate supplements PowerShell rather than replacing it. It works well for standard Microsoft 365 tasks and individual use, but GUI-based automation tends to break down at enterprise scale, where you need more control, logging and customization. PowerShell, for example inside an Azure Function, can handle the parts of a flow that need deeper work.
