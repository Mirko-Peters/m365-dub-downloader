## FAQ

**Why use Azure Functions instead of standard connectors for Copilot plugins?**

Standard connectors are built for moving data, not for heavy computation or complex business rules. Chaining them adds latency, and low-code expressions in Power Automate hit limits quickly. Azure Functions give developers type-safe C# code, enterprise libraries, caching and retry logic, and plug back into Power Platform through an OpenAPI spec and a custom connector.

**How do you write an OpenAPI spec that Copilot actually uses?**

Write it for the language model, not for developers. Use stable, verb-based operation IDs, and descriptions that say when to use each operation and which user intent triggers it. Add explicit parameter formats with examples, define every response code with a structured error schema, and expose only the high-value operations Copilot needs.

**Which Azure Functions hosting plan works best for Copilot plugins?**

Flex Consumption with one or two always-ready instances fits most Copilot plugins, according to the episode. Those instances stay initialized, so baseline traffic avoids cold starts that can take seconds on the classic Consumption plan. The Premium plan also removes cold starts but charges for reserved compute even when traffic is low, such as outside business hours.
