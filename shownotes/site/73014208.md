## FAQ

**What is the difference between a vector and an embedding?**

A vector is simply a list of numbers describing something, while an embedding is a vector that represents meaning. An embedding model, such as Azure OpenAI's text-embedding-3-small, reads text and places it in a high-dimensional space, so related phrases like red jacket and crimson coat end up as close neighbors.

**Do I need a separate vector database on Azure?**

Not necessarily. The episode explains that Microsoft is adding vector capabilities to platforms you already use instead of pushing a specialist database. Azure AI Search, Azure Cosmos DB, SQL Server 2025 and Azure SQL Database all support vectors, so you can store embeddings next to existing data and keep your current skills.

**How do I keep vector embeddings in sync when documents change?**

Use incremental vector ETL: extract only new or changed documents, chunk and embed them, then load the vectors with metadata. Store the source reference, embedding model name and version and a timestamp, because without them you cannot trace results, re-embed after a model upgrade or support compliance audits. Embedding costs grow by token.
