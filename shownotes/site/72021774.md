## Key takeaways

- Agentic coding works best like pair programming: start with a plan and a product requirements document, generate prompts from it and supervise the agent's output with real technical knowledge.
- Power Platform makers should start working in Visual Studio Code with tools such as the Dataverse MCP server, agent [skills](https://www.m365.fm/entity/agent-skill/?utm_source=podcast&utm_medium=shownotes&utm_campaign=the-evolution-of-agentic-coding-with-nick-doelman-mvp-mct), GitHub Copilot and Claude Code, while Dataverse remains the governed data core.
- Customers should keep control of prompts, skills and agent-generated documentation alongside their source code, and organizations should retest AI tools regularly because capabilities change fast.

## FAQ

**What is agentic coding in Power Platform development?**

Agentic coding means working with an AI coding agent like a pair programmer instead of starting from a blank editor. Nick Doelman starts with a plan and a product requirements document, has the agent turn it into prompts, then supervises and tests the generated code. The developer becomes more of a supervisor but still needs technical knowledge.

**Why should Power Apps makers start using Visual Studio Code?**

Because much of the new agentic tooling lives there. Nick now spends most of his time in Visual Studio Code, using the Dataverse MCP server, Dataverse skills and coding agents such as GitHub Copilot or Claude Code to design data models and create tables through natural language. He advises makers to load it, experiment and not be scared.

**What should customers keep when a partner builds a code app with AI agents?**

Customers should keep the original prompts along with the source code and unmanaged solutions. Nick has his agent document what it built and write a prompt that can regenerate it, then stores that with test cases and the skills used in the repository. Without those assets, adjusting or refactoring an app later becomes difficult.
