## Key takeaways

- Polling Microsoft Graph wastes thousands of requests, still misses real-time changes and can push your app into throttling.
- A Graph webhook needs a subscription with notification URL, resource, change type and expiration, plus a validation handshake that echoes the token as plain text.
- Acknowledge notifications within seconds, process them asynchronously, renew subscriptions before they expire and use Delta query as a safety net for missed changes.

## FAQ

**How does the Microsoft Graph webhook validation handshake work?**

Graph sends a test POST with a validationToken query parameter to your notification URL, and your endpoint must echo it back within 10 seconds. The response must be plain text with a text/plain content type, not JSON. The validation service negotiates TLS 1.2, so an endpoint accepting only TLS 1.3 fails before your code runs.

**How fast must my endpoint respond to Microsoft Graph change notifications?**

Graph expects a 200-level response within three seconds. If over 10% of responses exceed that in a 10-minute window, the endpoint is marked slow and notifications are delayed. If over 15% exceed 10 seconds, it is marked drop and notifications are lost for good. So acknowledge immediately and process asynchronously through a queue.

**How long do Microsoft Graph subscriptions last and how do you renew them?**

Subscriptions expire after a resource-specific maximum, around three days for users and groups and up to 30 days for drive items. You renew by sending a PATCH request with a new expiration date time before the current one passes. Lifecycle notifications warn you about expiring subscriptions, and Delta query catches anything missed meanwhile.
