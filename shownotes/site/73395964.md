## Key takeaways

- Azure Local runs virtual machines, containers and selected Azure services on validated hardware at your own site, while Azure provides management, monitoring, policy and security.
- Azure Arc is the management layer that connects any outside infrastructure to Azure, whereas Azure Local is the hyperconverged platform where local workloads actually run.
- Choose Azure Local when latency, data location rules, required offline operation or direct control demand it, and start every decision with the workload rather than the hardware.

## FAQ

**What is the difference between Azure Arc and Azure Local?**

Azure Arc is the management layer, while Azure Local is the platform where local workloads actually run. Arc connects servers, Kubernetes clusters and other resources outside Azure, including systems that are not Azure Local, to the Azure portal. Azure Local provides validated hardware and clustered software for virtual machines, containers and selected Azure services.

**Is Azure Local the same as Azure Stack HCI?**

Largely, yes. Azure Stack HCI is the older name and is now part of Azure Local, so older articles, training and diagrams describe much of the same foundation. Microsoft now uses Azure Local as the broader name for Azure-connected infrastructure running at your site, built on hyperconverged clusters with Hyper-V running the virtual machines.

**When does Azure Local make sense for a workload?**

Azure Local fits when a workload needs a very fast response, data must stay in a specific place, legal or company rules limit where data goes, the site must keep working without connectivity, or you need direct local control. A simple web app already running well in public Azure, or a very small workload, may not justify local hardware.
