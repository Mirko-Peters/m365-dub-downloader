## FAQ

**What is the difference between system-assigned and user-assigned managed identities?**

The difference is lifecycle. A system-assigned identity is tied one to one to a single resource, such as an App Service or a VM, and is deleted together with it. A user-assigned identity is a standalone Azure resource you create first, attach to many resources, and keep even after those resources are deleted.

**How does an app get an access token with a managed identity?**

The app asks the Instance Metadata Service at 169.254.169.254 for a token. Azure confirms the resource has a managed identity enabled, and IMDS returns a short-lived OAuth 2.0 access token from Entra ID. With the Azure SDKs, DefaultAzureCredential handles this automatically and caches and refreshes the token in the background.

**Can I use managed identities outside of Azure?**

No. Managed identities only work for workloads running in Azure, because only Azure resources can reach the IMDS endpoint. On-premises servers, self-hosted GitHub Actions runners, AWS or GCP workloads and third-party SaaS tools need service principals with Key Vault and automated rotation, or workload identity federation for external tokens.
