## FAQ

**How does single sign-on work?**

Single sign-on works by letting one trusted identity provider vouch for you to many apps. When you open an app, it sends you to the provider, which checks your existing session or asks you to sign in, then returns a signed token. The app verifies that signature and lets you in without ever seeing your password.

**What is the difference between SAML and OpenID Connect?**

SAML is the older protocol that wraps user details in XML and is still common in enterprise software, while OpenID Connect is built on OAuth 2.0 and uses compact JSON tokens. Microsoft treats both as secure but recommends OpenID Connect for new cloud apps, and many companies simply run both side by side.

**Is single sign-on a security risk?**

Single sign-on is a single point of failure, because one login opens every connected app. An outage can lock people out everywhere, and a stolen token can let an attacker skip the password and sometimes MFA. The usual fixes are phishing-resistant MFA, watching sign-in logs, least-privilege access, fast offboarding and managed-device or location rules.
