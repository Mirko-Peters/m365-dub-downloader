## Key takeaways

- Azure Firewall is a fully managed, cloud-native firewall service with built-in high availability and autoscaling that inspects inbound, outbound and east-west traffic.
- Basic, Standard and Premium SKUs add capabilities step by step, from IP and port filtering to threat intelligence in deny mode, web categories, TLS inspection, IDPS and URL filtering.
- Traffic is only inspected if it passes through the firewall, so a hub-and-spoke design, correctly ordered NAT, network and application rules, and cost controls like the Log Analytics basic table plan matter as much as the SKU.

## FAQ

**Which Azure Firewall SKU should I choose?**

Start with Standard for most enterprise workloads. Basic suits small environments and dev or test, with threat intelligence in alert mode only. Standard adds deny mode, web category filtering and custom DNS. Premium adds TLS inspection, IDPS and URL filtering, so reserve it for sensitive or regulated data that needs deep inspection.

**In what order does Azure Firewall process its rules?**

Azure Firewall processes NAT rules first, then network rules, then application rules, and within each type lower priority numbers are evaluated first. This matters because a broad network rule that allows all traffic is hit before your application rules, which may then never be evaluated and become useless.

**How can I reduce Azure Firewall costs?**

Use the Log Analytics basic table plan for firewall logs, which the episode says can save up to 80 percent on ingestion costs. Stop non-production firewalls outside working hours with Azure Automation, review routing so only necessary traffic passes through, and use private endpoints so trusted services avoid inspection.
