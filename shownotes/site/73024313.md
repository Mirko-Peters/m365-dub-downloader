Kubernetes is the industry standard for running containers, but operating it yourself is a full-time job. This plain-English episode is for developers and IT pros new to containers: it walks through what Azure Kubernetes Service manages for you, from the control plane to nodes, networking and security, plus what it really costs and the pitfalls to avoid.

## Key takeaways

- AKS is managed Kubernetes: Microsoft runs and patches the control plane, while you choose, scale and pay for the worker node virtual machines.
- Plan subnet sizes for growth from day one and secure clusters in layers with [Entra ID](https://www.m365.fm/entity/entra-id/?utm_source=podcast&utm_medium=shownotes&utm_campaign=azure-kubernetes-service-aks-simply-explained) and Kubernetes RBAC, private clusters, Azure Policy and Key Vault for secrets.
- Most AKS cost comes from worker nodes, so right-size them, use the cluster autoscaler, reservations or spot VMs, and avoid AKS for simple monolithic apps.

## FAQ

**How much does Azure Kubernetes Service cost?**

Most of the AKS bill comes from worker node VMs, storage and networking, not the control plane. At the time of recording, the free tier had no SLA, Standard cost about $72 per cluster per month, and Premium about $432. A small general-purpose D-series node in East US ran about $70 per month, reducible with reservations or spot VMs.

**What does Microsoft manage in AKS and what do I manage?**

Microsoft runs the control plane, including the API server, scheduler, controller manager and etcd, and handles its patching, backups and monitoring. You choose the size and number of worker nodes, decide when upgrades happen, and bring your containerized applications, configurations and deployment pipelines. You still need to understand pods, deployments and services.

**Why does subnet size matter when creating an AKS cluster?**

Subnet size matters because AKS reserves IP addresses per node and you cannot expand the subnet after the cluster is created. A /28 subnet may work for a small test cluster but blocks growth later, forcing a rebuild or migration to a new node pool. The episode suggests planning for growth, with /24 as a reasonable starting point.
