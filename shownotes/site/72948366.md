## FAQ

**What is the difference between service-direct and agent-based faults in Azure Chaos Studio?**

Service-direct faults run through the Azure control plane, while agent-based faults need a small agent inside the virtual machine. Service-direct faults use Azure's own APIs, for example to shut down a VM, with no agent. Agent-based faults simulate problems inside the operating system, such as driving CPU to 100%, filling memory or killing a specific process.

**How are Azure Chaos Studio experiments structured?**

An experiment is a blueprint made of steps, branches and actions run against onboarded targets. Steps run one after another to model a timeline. Branches inside a step run in parallel, so several faults can hit at once. Actions are the actual faults, like CPU pressure, network delay or VM shutdown, and only faults enabled on a target can run.

**How do I run Azure Chaos Studio experiments safely?**

Start small in dev or staging with a single VM and a single fault, and only move to production once you trust your setup. Each experiment's managed identity starts with zero permissions, so grant only what it needs. Enable only the faults you accept per target, watch progress live and cancel immediately if something looks wrong.
