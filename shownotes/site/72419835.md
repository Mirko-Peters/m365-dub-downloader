## Key takeaways

- Infrastructure as code makes deployments repeatable, reduces typos and helps detect configuration drift compared with manual changes in the Azure portal.

## FAQ

**Should I start infrastructure as code with Bicep or Terraform?**

For a Microsoft-only environment, Maik usually recommends Bicep because it is easier to start with. Terraform works across AWS, Azure, Google and more, and keeps a state file, but getting state management right is where many people go wrong. If other clouds are planned, Terraform becomes the stronger choice.

**How can infrastructure as code pipelines avoid storing secrets?**

Use managed identities with federated identity credentials so a GitHub Actions workflow can authenticate without any stored secret. Where secrets are still needed, Maik's team keeps them as environment secrets in GitHub Enterprise or references them from Key Vault. The aim is to stop maintaining secrets yourself and grant identities only specific rights.

**How should teams validate AI-generated infrastructure code?**

Review every line before deploying, never push generated code straight to Azure. Maik uses GitHub Copilot with prompt files and instructions so output follows company conventions, then reads through it line by line. In his company, anyone who cannot explain a line in their pull request is sent back to start again.
