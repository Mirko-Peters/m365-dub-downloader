## FAQ

**What is indirect prompt injection in Microsoft 365 Copilot?**

Indirect prompt injection hides instructions in content Copilot retrieves, such as SharePoint pages, email footers, document metadata or Teams chats. Because RAG places retrieved text into the same context window as the system prompt, the model can treat that hidden text as commands. The attacker never needs to interact with Copilot directly.

**Why don't system prompts and access controls stop prompt injection?**

They address different problems. Access controls decide which data a user can retrieve, not how the model interprets it, so a permitted document can still carry a payload. A system prompt is just another string competing for attention, and long, dense retrieved documents or context overflow attacks can push it out of focus.

**How does the dual LLM pattern protect against prompt injection?**

It keeps untrusted text away from any model that can act. A quarantined LLM reads retrieved content but has no tools or sensitive data, while a privileged LLM holds the tools. A controller written as regular software, not a language model, passes only schema-validated structured output between them and rejects anything unexpected.
