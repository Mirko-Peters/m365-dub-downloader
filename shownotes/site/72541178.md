Private RAG projects focus on where data lives, but often lose the permissions that decided who could see it. This episode is for CISOs, architects and engineers building AI retrieval on SharePoint and Microsoft 365 data, and explains how permission-aware retrieval, scoped identity and policy engines stop a knowledge system from becoming an insider data leak.

## Key takeaways

- Keeping data in a sovereign region does not protect it: if SharePoint permissions are lost during extraction, a RAG index exposes documents to anyone who can query it.
- Capture ACLs as Entra ID-based metadata at ingestion and filter by user and group before retrieval, for example with [Azure AI Search](https://www.m365.fm/entity/azure-ai-search/?utm_source=podcast&utm_medium=shownotes&utm_campaign=private-rag-isnt-enough-the-missing-layer-between-data-sovereignty-and-data-security), instead of filtering afterwards or relying on the prompt.
- Separate responsibilities across agents, use scoped tokens via OAuth 2.0 token exchange and a deterministic policy decision point, and monitor retrieval behavior with zero trust at every hop.

## FAQ

**Is a self-hosted or EU-hosted RAG system automatically secure?**

No, hosting location only answers where data sits, not who can see it. If SharePoint permissions are lost during extraction, anyone who can query the index may receive confidential content. A self-hosted vector database without role-based access control is less secure than a managed cloud database that enforces per-user filtering, according to the episode.

**How do you keep SharePoint permissions in a RAG index with Azure AI Search?**

You set indexer permission options on the SharePoint data source so the indexer stores user and group IDs as metadata fields. Use stable Microsoft Entra ID object IDs rather than names or email addresses. At query time, a filter on tenant, user and group IDs is applied before the search runs, not afterwards.

**Why can't a system prompt enforce access control in a RAG system?**

Because language models follow instructions rather than enforce rules, and prompts can be bypassed through prompt injection or fail silently. Once a document reaches the context window, the model treats it as evidence. The episode recommends a deterministic policy decision point outside the model, such as OpenFGA, so unauthorized documents never reach the model.
