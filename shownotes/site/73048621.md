## Key takeaways

- Blob Storage is flat object storage for unstructured data, organized as storage account, container and blob.
- Block, append and page blobs serve files, logs and VM disks, while hot, cool, cold and archive tiers trade storage cost against access cost, automated by lifecycle management rules.
- Prefer Microsoft Entra ID with [Azure](https://www.m365.fm/entity/azure/?utm_source=podcast&utm_medium=shownotes&utm_campaign=azure-blob-storage-simply-explained) RBAC over account keys and SAS tokens, and choose LRS, ZRS or GZRS based on how critical the data is.

## FAQ

**What is the difference between block, append and page blobs?**

Block blobs store files people upload or download, append blobs store continuous streams like logs, and page blobs serve as virtual machine disks. Block blobs upload in parallel blocks, append blobs only allow adding data at the end, and page blobs use fixed 512-byte pages that support random read and write access.

**How do the Azure Blob Storage hot, cool, cold and archive tiers differ?**

Each tier trades storage cost against access cost. Hot has the highest storage but lowest transaction costs, cool suits data accessed less than monthly, and cold suits data touched roughly every 90 days. Archive is cheapest but offline, so blobs must be rehydrated first, which takes 2 to 15 hours according to the episode.

**Should I use SAS tokens or Microsoft Entra ID for Blob Storage access?**

The episode recommends moving away from account keys and SAS tokens toward Microsoft Entra ID with Azure RBAC. Roles such as Storage Blob Data Reader grant precise permissions, use the same identity system as other Azure services and let you audit access. SAS tokens remain handy for temporary, time-limited access like a 24-hour download link.
