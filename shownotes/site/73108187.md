## Key takeaways

- Fabric Data Factory is the built-in data integration engine of Microsoft Fabric, with capacity-based pricing and OneLake as automatic storage instead of linked services and storage accounts.
- Pipelines orchestrate, Dataflow Gen2 transforms with [Power Query](https://www.m365.fm/entity/power-query/?utm_source=podcast&utm_medium=shownotes&utm_campaign=microsoft-fabric-data-factory-simply-explained), copy jobs handle continuous incremental ingestion and mirroring replicates operational databases in near real time.
- If your ADF bill is low and you are not on Fabric, staying with ADF can make sense; if you already have Fabric capacity, pipelines cost very little extra.

## FAQ

**What is the difference between Fabric Data Factory and Azure Data Factory?**

Fabric Data Factory uses capacity-based pricing and OneLake, while Azure Data Factory charges per activity run and needs storage accounts and linked services. In Fabric, connections are defined inline, pipelines can send email or Teams messages directly, and deployment pipelines promote work between workspaces. SSIS support and managed VNet were still missing at the time of recording.

**When should I use a copy job instead of a copy activity in Fabric?**

Use a copy job for continuous, low-maintenance ingestion into OneLake. It tracks inserts, updates and deletes through change data capture and supports SCD type 2 for full history, so no manual watermarking is needed. A copy activity in a pipeline fits one-off or scheduled bulk loads where you need more control over mappings and error handling.

**How does mirroring work in Microsoft Fabric?**

Mirroring continuously replicates an operational database into OneLake by reading its transaction log, so inserts, updates and deletes appear within minutes without any code. The episode names Azure SQL Database, Azure Cosmos DB and Snowflake as sources. Compute and storage are free up to a limit, and Power BI reports can run on mirrored data without affecting the source.
