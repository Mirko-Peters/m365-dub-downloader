## Key takeaways

- A Fabric shortcut is a pointer to data at a target path, so deleting the shortcut never deletes the source data.
- Place shortcuts under Tables when the target is Delta and must be queryable in SQL and Power BI, and under Files for raw data you plan to process.
- Shortcuts trade copies for dependency and first-read latency, so copy data instead when it needs heavy transformation, must stay in a region, or needs full maintenance control.

## FAQ

**Does deleting a Fabric shortcut delete the source data?**

No, deleting the shortcut itself leaves the data at the target untouched, because a shortcut is only a pointer. The risk is deleting files or folders inside a writable shortcut: if you have delete permission at the target, that content is removed at the source. Check for shortcuts before cleaning up any folder that might contain one.

**Should I create a Fabric shortcut under Tables or Files?**

Use Tables when the target is in Delta format and you want to query it with SQL or use it in Power BI. Tables shortcuts must sit at the top level and names cannot contain spaces. Use Files for raw data of any format you plan to process, for example with Spark, since nothing there becomes a table automatically.

**When should I copy data instead of using a Fabric shortcut?**

Copy the data when it needs heavy transformation before anyone can use it, when a rule requires it to stay in a specific region, or when you need full control over table maintenance. Shortcuts also add dependency and slower first reads from remote sources, though shortcut caching helps repeated reads for files under one gigabyte.
