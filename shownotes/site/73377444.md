## Key takeaways

- Azure should not be treated as a data center: cloud success is an adoption exercise across people, processes and technology, not only a technical migration.
- An Azure landing zone separates the platform landing zone for shared security, management, networking and identity from application landing zones built from subscriptions with pre-provisioned utilities and policies.
- Platform engineering builds standardized, self-service building blocks for developers, using Azure Policy remediation, infrastructure as code with Bicep or Terraform, Azure Verified Modules and [Azure DevOps](https://www.m365.fm/entity/azure-devops/?utm_source=podcast&utm_medium=shownotes&utm_campaign=azure-platform-engineering-azure-landing-zones-cloud-adoption-framework-jev-suchoi) or GitHub as guardrails that help rather than block.

## FAQ

**What is the difference between a platform landing zone and an application landing zone?**

The platform landing zone holds the shared core services everyone relies on: security, management, networking and identity. Application landing zones are sets of Azure subscriptions, usually one per environment, that the platform team prepares with utilities such as a virtual network, key vault, storage and logging, plus Azure Policy assignments for compliance requirements like GDPR.

**How do the Cloud Adoption Framework and the Well-Architected Framework differ?**

The Cloud Adoption Framework covers how to adopt Azure, including people, processes, operating models and skills, not only technology. The Well-Architected Framework focuses on designing workloads soundly, using six pillars such as reliability, security, cost optimization, operational excellence and performance efficiency. Jev describes them as existing side by side rather than one replacing the other.

**How can Azure Policy help developers instead of only blocking them?**

Remediation policies, for example deployIfNotExists, fix settings automatically instead of just denying a deployment. Jev's example is a web app deployed without SSL: the policy detects it and enables HTTPS for the team. Developers are not bothered with that compliance detail, while basic deny policies still enforce rules such as allowed regions.
