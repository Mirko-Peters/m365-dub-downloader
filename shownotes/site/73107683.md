## FAQ

**Does Microsoft Defender for Identity protect on-premises Active Directory or Entra ID?**

Defender for Identity protects on-premises identity infrastructure: domain controllers, Active Directory and AD FS servers. It runs as a cloud service but watches what lives in your own data center. Cloud sign-in risks such as anonymous IP addresses or atypical travel are handled by Microsoft Entra ID Protection, and Microsoft recommends both for hybrid environments.

**How does Defender for Identity detect attacks?**

It uses lightweight sensors on domain controllers that read network traffic, Windows events and authentication activity and forward them to a cloud service. That service learns a baseline for every user, such as login times and usual workstations, and alerts on deviations, mapping detections like pass-the-hash or Kerberoasting to the MITRE ATT&CK framework.

**What are honeytoken accounts in Defender for Identity?**

Honeytoken accounts are decoy user accounts that nobody should ever use, given tempting names like Exchange Admin or Domain Backup Service. Because they have no legitimate purpose, any authentication with one triggers an alert immediately, without custom monitoring or detection rules. You set them up in the Defender portal under Settings, Identities, Honeytokens in about 30 seconds.
