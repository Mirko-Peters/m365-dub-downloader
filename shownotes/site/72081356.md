## Key takeaways

- Use the LLM as the reasoning layer that understands requests and picks tools, while deterministic, self-written workflows and tools do the actual business work.
- Production-grade agents need orchestration, state and memory management, evaluation loops, observability and clear decision boundaries, which Microsoft Foundry provides largely built in.
- Specialised small language models and domain-specific agents will outperform general-purpose models in the enterprise on cost, latency and fit, but humans stay in the loop.

## FAQ

**Why do so many AI agent projects fail in production?**

Because teams put an LLM everywhere, including the business logic itself, instead of using it as the reasoning layer. Karthikeyan argues the LLM should understand the request and decide which tools to call, while deterministic, self-written workflows and tools do the real work, supported by orchestration, memory management and evaluation.

**What do orchestration, memory and evaluation mean in an AI agent system?**

Orchestration decides which agents to call and in what order, memory makes sure nothing important is forgotten, and evaluation validates the outcomes. In the episode's refund example, an orchestrator calls only the few agents needed to verify the order, check whether the item is returnable and confirm the return window.

**Will small language models outperform large general-purpose models in the enterprise?**

Karthikeyan expects specialised small language models to win in the enterprise. He gives three reasons: much lower cost, lower latency and fine-tuning for the specific problem. He sees the future in hybrid architectures and domain-specific agents, while fully autonomous employees remain hype because humans stay in the loop.
