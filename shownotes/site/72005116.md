## Key takeaways

- Microsoft Graph is the API layer behind nearly every Microsoft cloud service, so admins who learn its documented endpoints and permissions can automate almost anything they would otherwise click in a portal.
- Hard-coded passwords and secrets remain the biggest automation security mistake; use Azure Key Vault, Azure Automation credentials or, best of all, managed identities that remove secrets entirely.
- Apply least privilege everywhere: separate app registrations per service, grant only the Graph permissions an endpoint needs, and treat Azure Automation webhooks like secrets.

## FAQ

**How do I avoid hard-coded secrets in Azure Automation scripts?**

Store credentials outside the script, ideally in Azure Key Vault accessed through a managed identity. Ahmed Uzejnovic calls hard-coded passwords and secrets the biggest automation security mistake. Azure Automation variables and credentials are better than plain text, and Key Vault also works from a hybrid worker on-premises, so scripts never need to carry passwords.

**Why use a managed identity for Azure Automation instead of an app registration secret?**

A managed identity has no secret you can leak or let expire. Microsoft manages the underlying service principal and its credentials, much like a group managed service account. You enable the managed identity on the Automation account, grant it only the roles it needs, such as Intune device access, and connect with one line of code.

**How should Azure Automation webhooks be secured?**

Treat every webhook URL like a secret. Anyone who obtains the link can call your runbook, and if the webhook accepts parameters they can make it do real work. Ahmed also recommends that only administrators with a defined process trigger runbooks through the API, through an app registration that holds only the rights it needs, never one shared registration.
