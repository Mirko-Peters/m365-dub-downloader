## Key takeaways

- Azure Image Builder turns hand-built golden images into a repeatable process driven by an image template with a source, customizations, validation, distribution and versioning.
- Azure Compute Gallery organizes images into definitions and versions, replicates them to regions and enables rollback to a known good version.

## FAQ

**What does Azure Image Builder actually do?**

Azure Image Builder creates customized virtual machine images from instructions you define in an image template. It starts from a source image, runs your scripts, validates the result and publishes it, for example to Azure Compute Gallery. It builds only the image; you create one VM or many from that finished image later.

**Why does my Azure Image Builder build fail?**

Most failures come from permissions, network access, policies and scripts rather than the image itself. Check the managed identity's roles, whether the build VM can reach installers and update sources, Azure Policy assignments and registered resource providers. Then read the customization and validation logs in the Packer logs container of the staging storage account.

**Why use Azure Compute Gallery instead of a managed image?**

Azure Compute Gallery adds structure a managed image lacks: image definitions for image families, image versions for each exact release, replication to the regions where you deploy, and replica counts for large rollouts. Versions also let you return to an earlier known good image while you investigate a problem, instead of rebuilding from memory.
