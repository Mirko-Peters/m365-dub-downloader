## Key takeaways

- Virtual machine scale sets create matching VM instances from one shared setup, enabling horizontal scaling instead of ever-larger single machines.
- A load balancer or Application Gateway with health probes routes traffic to healthy instances, while autoscale rules and availability zones handle demand and failures.
- Scale sets fit stateless, repeatable workloads such as web front ends, APIs and queue workers; stateful data must live outside the instances.

## FAQ

**What is the difference between uniform and flexible orchestration in Azure Virtual Machine Scale Sets?**

Uniform treats the scale set as one identical fleet with the same VM size, image and configuration, which suits web front ends and APIs. Flexible lets you manage instances more like normal VMs, mixing sizes or regular and Spot VMs. You choose the mode when creating the scale set and cannot change it later.

**How does autoscale decide when to add or remove VMs?**

Autoscale follows rules between a minimum and maximum instance count that you set. Rules can watch metrics such as average CPU, network traffic, response times or queue length, run on a schedule ahead of known rushes, or use predictive autoscale based on past patterns. Autoscale is not switched on automatically when you create a scale set.

**Does an Azure virtual machine scale set cost extra?**

No, a scale set itself adds no separate service charge. You pay for what runs underneath it, including VM compute time, storage and network use. When the set grows from two VMs to ten, costs rise with the extra machines, and when it scales in, running costs drop with the removed instances.
