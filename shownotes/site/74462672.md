## Key takeaways

- Business Central extensions add fields, pages, reports, permissions and integrations in their own package, so the standard application stays intact and updates cause less repair work.
- Use Microsoft or ISV apps from [AppSource](https://www.m365.fm/entity/microsoft-appsource/?utm_source=podcast&utm_medium=shownotes&utm_campaign=dynamics-365-business-central-extensions-simply-explained) for common needs and per-tenant extensions only for processes unique to your company, with a clear owner for support and testing.
- Before installing, check publisher, supported versions, pricing, documentation, data flows and permissions, test real cases in a sandbox, and keep a record of every installed extension.

## FAQ

**What is a per-tenant extension in Business Central?**

A per-tenant extension (PTE) is an app built for one company's Business Central environment only, not published for every customer. It fits unusual processes, such as a distributor's complex delivery charge rules. The trade-off is ownership: someone must keep notes, test changes and arrange support when the process or Business Central changes.

**Why do Business Central extensions make updates easier than direct code changes?**

Extensions keep their code in a separate package from the standard application, so Microsoft can update the core while the extension stays intact. Directly changed code could clash with updates and needed repair and testing. Updates still need some attention, because an extension may depend on another app and its publisher may need to release a compatible version.

**What should you check about data and security before installing a Business Central app?**

Ask which data the app can see, change or send elsewhere. Have the publisher explain where data goes, which region stores it, how long copies are kept and what reaches any AI service. Give the app only the permissions it needs, check which users get its permission sets, and let IT, finance, security and compliance review sensitive apps.
