## Key takeaways

- A passkey is a key pair whose private half never leaves your device, so there is no shared secret that a phishing page could steal.
- Synced passkeys suit most users because they survive a lost device, while administrators and privileged accounts should use device-bound passkeys such as security keys or Microsoft Authenticator.
- Passkeys are becoming the default sign-in in [Microsoft Entra ID](https://www.m365.fm/entity/entra-id/?utm_source=podcast&utm_medium=shownotes&utm_campaign=passkeys-and-fido2-simply-explained), so set up a backup passkey early and plan for limits such as visibility of synced copies.

## FAQ

**What is the difference between synced and device-bound passkeys?**

A synced passkey is stored in a cloud account such as iCloud Keychain or Google Password Manager and follows you to new devices, while a device-bound passkey never leaves one security key or the Microsoft Authenticator app. Microsoft recommends synced passkeys for most users and device-bound ones for administrators and highly privileged accounts.

**Why can't passkeys be phished?**

Passkeys resist phishing because there is no secret to hand over. Your private key stays on your device and only signs a one-time challenge from the server. The credential is also origin bound, so it only answers for the real site and stays silent on a copied sign-in page, unlike a password or a one-time code.

**What happens if I lose the phone with my passkey on it?**

A synced passkey comes back when you sign in to the same cloud account on a new phone, so losing the device is not a lockout. A device-bound passkey is gone with the device, which is why you should register a second passkey during setup. Administrators can also revoke a passkey from your account.
