Microsoft MVP and MCT Tchesco Ayih shares with makers and developers how to design user-centric canvas apps, when to choose Copilot Studio agents over apps, and how AI, code apps and governance are shaping low-code development.

## Key takeaways

- Start Power Apps projects with a designed UI and user journey before adding data and features, and treat UX as an ongoing process refined through user feedback.
- Use Copilot Studio agents for simple information requests and step-by-step guidance, but build an app when forms are complex or users need request history.
- AI speeds up low-code development, but developers stay relevant through prompt engineering, verifying AI output and governing AI in the tenant.

## FAQ

**Should you design the UI before building a Power Apps canvas app?**

Yes, the guest starts every canvas app with a fully designed UI screen, then connects the database and adds features one by one. Starting with features tends to scatter buttons and galleries across screens. He also asks early whether users work in the field or at a desk, and builds mobile and desktop versions separately.

**When should you build a Copilot Studio agent instead of a Power App?**

Build an agent when users need basic information or step-by-step guidance, such as a new employee being onboarded through a chat. Build an app when forms become complex or users need to see the history of their requests. Both can work on the same data, for example in a leave request process.

**Will AI replace low-code developers?**

The guest does not think so, as long as developers learn prompt engineering and verify what AI produces. He treats AI like a junior colleague whose output he always checks before using it. Developers who ignore these tools, however, risk losing out to colleagues who finish in a day what takes a week manually.
