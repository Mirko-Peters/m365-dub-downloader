## Key takeaways

- Azure Compute Fleet lets you request a large pool of capacity across several acceptable VM sizes, zones and pricing models instead of betting a deployment on one exact SKU.
- Mixing on-demand VMs as a stable baseline with Spot VMs for extra throughput only works when progress lives outside the worker, in durable queues, checkpoints and retry-safe tasks.
- Virtual machine scale sets fit steady application tiers that serve user traffic, while Compute Fleet fits batch, simulation, rendering and other work that splits across many independent workers.

## FAQ

**What is Azure Compute Fleet?**

Azure Compute Fleet is a managed service for acquiring a large pool of VM capacity in one request. You list acceptable VM sizes, zones and on-demand or Spot pricing, and Azure finds a workable mix. The episode says one deployment can handle up to 10,000 VMs, but you still supply the image, network and software.

**What is the difference between Compute Fleet and virtual machine scale sets?**

Virtual machine scale sets scale a steady application tier as user traffic changes, usually with one known setup behind a load balancer. Compute Fleet gathers lots of flexible compute for jobs that split across independent workers, such as batch, simulation or rendering. You can combine both, with scale sets serving users and Compute Fleet supplying background workers.

**How do I use Spot VMs safely with Compute Fleet?**

Keep progress outside the worker VMs, because Azure can reclaim Spot VMs at any time. Use a durable queue so workers pull one task at a time, save checkpoints during long jobs and make every task safe to retry. Keep a baseline of on-demand VMs for minimum throughput, and set a cost limit before launching.
