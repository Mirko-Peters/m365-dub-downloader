## Key takeaways

- Git is a local-first version control system that records deliberate, named checkpoints called commits, so you can see what changed and return to an earlier version.
- Changes move from the working directory through the staging area into the local repository, while branches let you work safely without disturbing the trusted main version.
- GitHub adds a shared remote repository and pull requests for review and automated checks, turning separate computers into one team workflow: work, stage, commit, push, review, merge.

## FAQ

**What is the difference between Git and GitHub?**

Git is the version control tool on your computer that records your project history, while GitHub is an online platform where teams store, share and review that history. Git works locally and offline, so commits need no internet connection. GitHub adds a shared remote repository, push and pull, and pull requests for review.

**What is the staging area in Git?**

The staging area is a review tray where you choose which changes go into your next commit. You add selected files with git add, which neither saves them permanently nor sends anything online. This lets you commit a finished fix, like a password reset link, while leaving an unfinished redesign out of that checkpoint.

**What should you do when Git shows a merge conflict?**

Read both versions, decide which to keep or how to combine them, then save, mark the file resolved and create the merge commit. A conflict means two changes touched the same part of a file and Git needs a person to choose. If unsure, ask whoever wrote the other change; short-lived branches keep conflicts small.
