This episode is for developers and small teams who want modern container features without becoming Kubernetes admins: it explains Azure Container Apps, how KEDA, Dapr and Envoy power it, its limits, and what it costs.

## Key takeaways

- Azure Container Apps sits between Azure Container Instances and AKS, offering Kubernetes-level features like autoscaling, ingress and revisions while Microsoft manages the cluster.
- KEDA, Dapr and Envoy provide event-driven scaling to zero, microservice building blocks and managed ingress with traffic splitting out of the box.
- Start new container projects on Container Apps and move to AKS only if you need Helm, custom resources, Windows containers or full cluster control.

## FAQ

**When should I use Azure Container Apps instead of AKS?**

Use Azure Container Apps for most new web apps, APIs, microservices and event-driven workloads where you want autoscaling and ingress without managing a cluster. Choose AKS when you need full control over nodes, networking and security policies, Helm charts, custom resource definitions or Windows containers. For occasional one-off jobs, Azure Container Instances is enough.

**What are the limitations of Azure Container Apps?**

Azure Container Apps does not give you full Kubernetes flexibility. There is no access to the control plane, you cannot install custom Kubernetes plugins, and workload profiles are limited to roughly 10 to 12 VM sizes. It does not support Helm charts or custom resource definitions, and at the time of recording it ran Linux containers only.

**How is Azure Container Apps priced?**

Azure Container Apps offers a consumption plan and a dedicated plan. Consumption charges per second for active CPU and memory, applies a lower idle rate, costs nothing when scaled to zero, and includes two million free requests per month per subscription. The dedicated plan charges per hour for reserved workload profile VMs, giving predictable performance without cold starts.
