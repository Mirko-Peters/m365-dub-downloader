## Key takeaways

- Copilot's Graph grounding is retrieval-augmented generation, which searches from zero on every query and therefore cannot build memory or consistency over time.
- The LLM Wiki pattern compiles raw sources once into maintained, cross-linked pages governed by a schema and flags contradictions instead of silently averaging them.
- Start with one recurring high-value knowledge domain, clean up its sources with retention, content types and ownership, and give a named owner responsibility for the schema.

## FAQ

**Why does Microsoft 365 Copilot give different answers to the same question?**

Copilot gives different answers because its Graph grounding is retrieval-augmented generation, which searches from zero on every query. Phrasing a question differently triggers a different search, so different chunks reach the model. Nothing is stored between conversations, so Copilot cannot build on what it found yesterday or reconcile conflicting documents.

**What is the LLM Wiki pattern?**

The LLM Wiki pattern lets an AI read sources once and compile them into maintained, cross-linked pages instead of searching raw documents for every question. It has three layers: read-only raw sources, the wiki pages themselves, and a schema with rules for structure and updates. Contradicting new information is flagged rather than silently overwritten.

**Does an LLM Wiki replace RAG in Copilot?**

No, the episode recommends a hybrid. RAG keeps handling breadth across large, relatively static repositories, while a compiled wiki covers a narrow set of recurring, high-value topics such as onboarding, product positioning, compliance interpretations and project histories. A scheduled agent maintains those pages, and Copilot surfaces them preferentially alongside normal Graph grounding.
