## Key takeaways

- Azure Site Recovery continuously replicates entire servers to another region so workloads can fail over in minutes rather than being restored over hours or days.
- ASR does not replace backup: it replicates ransomware and corruption too, so mission-critical workloads need both backup for data and ASR for continuity.
- Replicate only workloads where downtime has real financial impact, use recovery plans for dependencies and DNS, and run test failovers regularly.

## FAQ

**What is Azure Site Recovery?**

Azure Site Recovery, or ASR, is a managed disaster recovery service that continuously replicates entire servers, including operating system, applications, data and settings, to a secondary location. When disaster strikes, you fail over to the replica and keep running, typically within minutes. After repairs, failback returns production to the original servers.

**Is Azure Site Recovery the same as Azure Backup?**

No, they solve different problems. Azure Backup saves your data and handles deletion, corruption, ransomware and single-file restores. ASR keeps the whole workload running during site-level disasters such as floods or power outages. ASR even replicates infections, so mission-critical workloads should use both: backup for data and ASR for continuity.

**How much does Azure Site Recovery cost?**

At the time of recording, ASR costs roughly $25 per protected instance per month, plus storage and data transfer. Each new protected instance gets 31 days free, which is useful for testing. Because costs add up quickly across many servers, the episode recommends replicating only workloads where downtime has real financial impact.
