## FAQ

**Why does Microsoft 365 Copilot give vague or outdated answers?**

Usually because retrieval cannot tell good sources from bad ones, not because the model is weak. Without metadata on recency, authority, topic and sensitivity, a three-year-old draft looks as authoritative as the approved policy. Copilot then blends versions and fills gaps with confident language, and overly broad permissions let it surface content users should not see.

**What is the difference between a taxonomy and an ontology in Microsoft 365?**

A taxonomy classifies content into buckets, while an ontology models how things connect. A taxonomy says a document is a policy for a given region. An ontology adds relationships such as authored by, belongs to, governed by, supersedes and applies to, which lets Copilot traverse context across customers, projects, policies and people instead of just retrieving documents.

**Where should an organization start when building a knowledge graph for Copilot?**

Start with a diagnostic: run the SharePoint Data Access Governance reports and document overshared sites, broad access groups and ownerless content. Then pick one workflow with measurable information friction, and define a minimal metadata schema for it, such as source, effective date, authority tier, topic and sensitivity, applied consistently to that focused content set.
