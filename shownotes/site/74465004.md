## FAQ

**What is the difference between virtual entities and virtual tables in Dataverse?**

There is no difference in concept, only in name. Virtual entities is the older term, and virtual tables is what they are often called now. Either way, a table definition in Dataverse points to records stored in another system, so Dynamics 365 shows live data without keeping a second copy.

**Which Dataverse features do not work with virtual tables?**

Virtual tables do not support Dataverse auditing, Dataverse search, charts and dashboards, offline caching, or calculated and rollup columns. Any audit history or calculation has to come from the source system or the data provider. Security also works differently: Dataverse controls access to the table, while the external system decides which rows and fields a user sees.

**When should I use a virtual table instead of syncing data into Dataverse?**

Use a virtual table when another system owns the data and users only need a live view while working in Dynamics 365. Choose a standard table with sync when you need offline access, detailed auditing, custom reporting or other Dataverse-only features. Decide carefully, because a virtual table cannot be converted into a standard table later.
