## Key takeaways

## FAQ

**Why do Power Automate flows break when an employee leaves?**

They break because the flow's connections run on that employee's personal account. When IT disables the account during offboarding, every flow, Power BI refresh or Logic App anchored to it stops. Password changes, MFA prompts and risky sign-in blocks cause the same failures, which is why production automation needs its own service principal identity.

**What is the difference between a managed identity and federated credentials?**

A managed identity is for workloads running inside Azure: Azure creates, stores and rotates it, and it disappears with the resource. Federated credentials cover external workloads such as GitHub pipelines, using OpenID Connect to exchange a trusted token for a short-lived access token, so no long-lived secret is stored in code or pipelines.

**How do you rotate a service principal secret without downtime?**

Use the dual credential pattern: add a new secret before deleting the old one. Microsoft Entra ID allows several valid credentials at once, so you configure the new secret, test it, then remove the old one. Storing the secret in Azure Key Vault and automating the update means flows always fetch the current value.
