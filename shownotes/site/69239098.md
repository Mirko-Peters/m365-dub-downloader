## FAQ

**What is a master agent in Copilot Studio multi-agent orchestration?**

A master agent is a thin control plane, not a smarter assistant. It holds workflow state, enforces deterministic gates, controls which tools may be called, normalizes identity and logs structured traces. It deliberately contains no business logic, delegating domain work to connected agents so it cannot invent steps, infer approvals or bypass segregation of duties.

**When should I use a connected agent instead of an embedded child agent?**

Use a connected agent for reusable enterprise capabilities and an embedded child agent for workflow-specific glue. Mirko's rule: if two teams depend on it, it needs its own authentication, a rollback plan or a separate kill switch, it must be connected. Anything touching identity, money or employment state should default to connected agents.

**Why do connected agents in Copilot Studio fail to show up or run?**

Usually because a boring prerequisite was skipped. The agent needs a clear description for routing, generative mode enabled, the setting that lets other agents connect to it switched on, and it must be published. After publishing, tool connections often need to be refreshed, so every connected capability needs an owner for credential maintenance.
