## Key takeaways

- Scaling Copilot Studio in regulated enterprises needs a strict ALM strategy with separate dev, QA and prod environments, DLP and connector policies, pipelines and approvals before agents reach production.
- Operations teams should be ready to quarantine an agent immediately when an incident occurs, and Purview auditing plus responsible AI checks make agent activity traceable.

## FAQ

**How should an enterprise set up environments for Copilot Studio?**

Use separate dev, QA and prod Power Platform environments with DLP and connector policies at each stage. In Isha Kapoor's setup, makers work only in dev with sharing turned off, a red team tests in QA, and only the operations team moves solutions to prod through a change request after code, owner and responsible AI approvals.

**What does it mean to quarantine a Copilot Studio agent?**

Quarantine stops an agent immediately without removing or undeploying it. The agent stays in the registry and remains visible to its audience in Teams or Microsoft 365 Copilot Chat, but users cannot interact with it until an investigation is finished. Isha Kapoor recommends keeping a quarantine script ready so operations can act on any incident.

**Which language model should you start with for Copilot Studio agents?**

Isha Kapoor advises starting with the bare minimum GPT-4.1 model from OpenAI and moving to higher models only for real needs such as reasoning. She considers GPT-5.1 suitable for production. Her organization turned off Anthropic models for security reasons and uses models deployed through OpenAI in its own Azure instance.
