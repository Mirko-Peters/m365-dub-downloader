Moving an old Windows app to an Azure VM does not remove its need for a classic domain with LDAP, Kerberos and Group Policy. This Knowledge Nugget shows IT admins and cloud architects where Microsoft Entra Domain Services fits next to Entra ID and Active Directory, and which limits to check before choosing it.

## Key takeaways

- Microsoft Entra Domain Services provides a managed Windows domain inside an Azure virtual network for legacy apps that still need LDAP, Kerberos, NTLM, domain join or Group Policy, without you running domain controllers.
- Identity data flows one way, from on-premises Active Directory or Entra ID into the managed domain, so users and groups must be managed in the source directory, and cloud-only users may need a password change before they can use it.
- New cloud apps should sign in directly through Entra ID; Domain Services does not fit apps that need LDAP write access, schema changes or full domain admin control.

## FAQ

**What is Microsoft Entra Domain Services?**

It is a managed Windows domain that runs inside your Azure virtual network. Microsoft runs and patches the domain controllers, while Azure virtual machines and older apps use domain join, LDAP, Kerberos, NTLM, DNS and Group Policy. Users and groups copy in from Entra ID, so the main identity record stays there.

**Why can't a cloud-only user sign in to a domain-joined VM after enabling Entra Domain Services?**

Usually because the user has not changed their password yet. Kerberos and NTLM need a protected form of password data, and for cloud-only users the managed domain typically gets it only after a password change following enablement. Until then the user can sign in to Microsoft 365 normally but still fails against the managed domain.

**When should you not use Microsoft Entra Domain Services?**

Skip it for new cloud apps, which should sign in directly through Entra ID. It also does not fit apps that need LDAP write access or Active Directory schema changes, or teams that require domain admin rights, direct domain controller access or a custom directory design. Those cases point to running Active Directory yourself.
