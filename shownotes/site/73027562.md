## Key takeaways

- Keyword search such as BM25 is precise for exact terms but misses meaning, while vector search with embeddings finds semantically similar content but can miss exact matches.
- [Azure AI Search](https://www.m365.fm/entity/azure-ai-search/?utm_source=podcast&utm_medium=shownotes&utm_campaign=azure-ai-search-simply-explained) combines both in hybrid search, merging results with Reciprocal Rank Fusion, and serves as the retrieval layer for RAG-based assistants and agents.
- Its building blocks are the data source, the indexer and the search index, and it delivers the most value on unstructured content such as PDFs, emails and support tickets.

## FAQ

**What is the difference between keyword search and vector search?**

Keyword search matches exact words, while vector search matches meaning. Keyword search, often ranked with BM25, weighs term frequency, document length and term rarity, so it nails product IDs and error codes. Vector search turns text into embeddings, long lists of numbers, and returns documents closest to the query, but it can miss exact codes.

**How does hybrid search in Azure AI Search rank results?**

Hybrid search runs keyword and vector search at the same time and merges both result lists with Reciprocal Rank Fusion. RRF looks at where each document ranks in the keyword results and in the vector results and gives it a combined score, so documents that do well in both get a boost and appear higher.

**What are the main components of Azure AI Search?**

Azure AI Search is built from a data source, an indexer and a search index. The data source can be Blob Storage, Azure SQL Database, Cosmos DB or SharePoint. The indexer extracts content, applies optional AI enrichment and builds the index, an inverted index that lets queries return results in milliseconds instead of scanning documents.
