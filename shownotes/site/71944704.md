## FAQ

**Which tags does an automated Azure cleanup engine need?**

The mandatory set is short: owner, environment, cost center, an expiry date or TTL, cleanup action and exception reason. Each one answers a deletion question. Values such as environment and cleanup action should be standardized, exception reasons should avoid free text, and tags should be set on the resource group and inherited through Azure Policy.

**In what order should Azure Policy be rolled out for tagging?**

Roll it out in the order audit, then modify, then deny. Audit gives visibility without breaking teams, modify fills gaps in existing resources through remediation tasks and inheritance, and deny comes last once teams know the contract and pipelines support it. Assign the policies at management group scope so rules stay consistent as the estate grows.

**What can break automated deletion of Azure resources?**

Resource locks, dependencies and soft-delete behavior are the main obstacles. A delete lock stops the call regardless of role assignments, child resources and managed-by relationships require a deletion order, and some services keep a recoverable state after deletion. Deny policies can also block the engine, so check locks first, exclude production and start in dry-run mode.
