## Key takeaways

- Infrastructure as code replaces manual portal deployments with declarative, version-controlled files that produce the same result every time they run.
- Bicep compiles to ARM JSON and uses the same Azure Resource Manager engine, but needs roughly half the code, infers dependencies automatically and adds modules and what-if previews.

## FAQ

**Should I use Bicep or Terraform for Azure?**

If you work mainly in Azure, Bicep is the simpler choice; if you work across several clouds, Terraform fits better. Bicep needs no state file, supports new Azure features on release day and is built by the Azure team. Many organizations combine both, using Bicep for platform and landing zones and Terraform for multi-cloud workloads.

**What do I need to start writing Bicep files?**

You need only the Azure CLI and the official Bicep extension for VS Code. The Azure CLI already includes Bicep, so no separate tool is required. Running az version shows both versions. The extension adds IntelliSense, syntax highlighting and real-time error checking, and activates when you save a file with the .bicep extension.

**What happens if I deploy the same Bicep file twice?**

Nothing changes on the second run, because Bicep deployments are idempotent. The first run creates the resources; the second compares Azure's current state with the file, finds nothing to change and finishes without errors or duplicates. That makes the file the single source of truth for what is deployed, instead of memory or written documentation.
