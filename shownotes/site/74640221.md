## Key takeaways

- An enterprise agent needs three pillars: a trigger, tools and actions, and clean, well-tagged knowledge sources rather than decades of unfiltered [SharePoint](https://www.m365.fm/entity/sharepoint/?utm_source=podcast&utm_medium=shownotes&utm_campaign=manpreet-singh) content.
- Governance, DLP and a Center of Excellence should be in place before agents roll out, with policies scoped to what each agent actually needs and tools like Agent 365 providing inventory and observability.
- The return on AI agents depends mostly on adoption, so every user needs role-based training on what an agent does and what input it expects.

## FAQ

**How do I build my first agent in Copilot Studio?**

Start with a blank agent in Copilot Studio, using a trial if you have no license. Add a knowledge source such as SharePoint, learn.microsoft.com or your company website. Then add a tool, for example a Power Automate action that sends you an email or adds a row to an Excel sheet.

**How can I reduce hallucinations in Copilot Studio agents?**

Clean up the knowledge first and index only current files with tags, metadata and descriptions instead of decades of SharePoint content. Many organizations also turn off web search so answers come only from grounded data. Manpreet Singh then tests agents with the Copilot Studio evaluation feature and asks users to rate answers.

**Why do AI agents often fail to deliver ROI?**

According to Manpreet Singh, the main factor is adoption. Announcing a new agent in an email is not enough, because users need to know what the agent does and what input it expects. He describes a company whose Microsoft 365 Copilot adoption went from none to 98 to 99 percent after persona-based training.
