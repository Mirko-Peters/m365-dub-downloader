## FAQ

**What is Conditional Access in Microsoft 365?**

Conditional Access is a policy engine that checks context after the password before granting access. It evaluates signals such as identity, location, device, application and sign-in risk, then applies if-then rules to grant access, block it or require MFA or a compliant device. It adds a layer on top of MFA rather than replacing it.

**Which Conditional Access policies should I create first?**

Start with three baseline policies: require strong MFA for all users, block legacy authentication, and require compliant devices for admins. Use authentication strengths to allow only methods like Microsoft Authenticator, FIDO2 security keys or Windows Hello for Business, and block legacy protocols such as IMAP and SMTP, which can bypass MFA entirely.

**How do I roll out Conditional Access without locking myself out?**

Create at least two break-glass accounts excluded from all policies before deploying anything. Then run each new policy in report-only mode for about a week, test it with the What If tool in the Microsoft Entra admin center, and roll it out in phases, starting with a small group such as the IT team.
