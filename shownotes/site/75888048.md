Managed service providers and multi-tenant enterprises have long juggled separate logins in every customer tenant. This episode explains how Azure Lighthouse replaces that with delegated, auditable access that the customer controls, and where its limits are. ## Key takeaways

- Azure Lighthouse lets a provider manage a customer's Azure resources from its own tenant through a registration definition and a registration assignment, with no account in the customer's directory.
- The customer chooses the scope and built-in role, sees every provider action in its own activity log and can remove the delegation at any time.
- Lighthouse covers Azure Resource Manager operations only, does not support the Owner role or data-access roles, and is a different product from [Microsoft](https://www.m365.fm/entity/microsoft/?utm_source=podcast&utm_medium=shownotes&utm_campaign=azure-lighthouse-simply-explained) 365 Lighthouse.

## FAQ

**How does Azure Lighthouse give a provider access to a customer's resources?**

Through two records deployed in the customer's account: a registration definition naming the provider and its allowed roles, and a registration assignment applying that to a subscription or resource group. Azure Resource Manager checks both are present on every request, and the customer's own administrator must run the deployment that creates them.

**Can Azure Lighthouse be used to read data inside Azure resources?**

No, Azure Lighthouse is a management tool, not a data tool. It covers requests that go through Azure Resource Manager, so it cannot read a secret from a key vault or open a file in a storage account. The Owner role, data-access roles and custom roles are not supported in a delegation.

**Is Azure Lighthouse the same as Microsoft 365 Lighthouse?**

No, they are separate products that only share a name. Azure Lighthouse lets a provider manage customers' Azure resources through delegated access from its own tenant. Microsoft 365 Lighthouse is a different tool that helps providers onboard, monitor and manage Microsoft 365 customers, so the two solve different problems for service providers.
